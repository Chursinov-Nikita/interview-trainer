@@@ js-01 | event-loop, async
Как работает Event Loop? В каком порядке выполнятся синхронный код, промисы и `setTimeout`?
???
JS однопоточный. Есть **стек вызовов**, очередь **микрозадач** (промисы, `queueMicrotask`, `MutationObserver`) и очередь **макрозадач** (`setTimeout`, события, I/O).

Цикл: выполнить синхронный код до опустошения стека → **все** микрозадачи → отрисовка (если нужна) → **одна** макрозадача → снова все микрозадачи…

```js
console.log(1);
setTimeout(() => console.log(2));
Promise.resolve().then(() => console.log(3));
console.log(4);
// 1 4 3 2
```

@@@ js-02 | замыкания, функции
Что такое замыкание? Приведи практический пример.
???
Функция + лексическое окружение, в котором она создана. Функция «помнит» переменные внешней области, даже когда внешняя функция уже завершилась.

```js
function counter() {
  let n = 0;
  return () => ++n;
}
const next = counter();
next(); // 1
next(); // 2
```

Применение: приватное состояние, фабрики функций, debounce/throttle, мемоизация, хуки React (и их ловушка — устаревшее замыкание).

@@@ js-03 | this, функции
Как определяется `this`?
???
Зависит от **способа вызова**, а не от места объявления:

- `obj.method()` → `obj`
- обычный вызов `fn()` → `undefined` в strict mode (иначе `globalThis`)
- `new Fn()` → новый объект
- `fn.call(ctx)`, `apply`, `bind` → `ctx`
- стрелочная функция своего `this` не имеет — берёт из внешней области

Ловушка: `const m = obj.method; m()` — контекст потерян.

@@@ js-04 | переменные, tdz
Чем отличаются `var`, `let` и `const`? Что такое TDZ?
???
- `var` — область видимости функции, всплывает со значением `undefined`, можно переобъявить.
- `let`/`const` — блочная область. Тоже всплывают, но до строки объявления находятся во **временной мёртвой зоне** (TDZ): обращение → `ReferenceError`.
- `const` запрещает переприсваивание, но не делает объект неизменяемым.

```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j)); // 0 1 2
```

@@@ js-05 | hoisting, переменные
Что такое hoisting (всплытие)?
???
При создании контекста объявления «поднимаются»:

- **Function Declaration** — целиком, можно вызвать до объявления;
- `var` — со значением `undefined`;
- `let`, `const`, `class` — без инициализации (TDZ).

Function Expression ведёт себя как переменная:

```js
hi(); // работает
function hi() {}

bye(); // TypeError: bye is not a function
var bye = () => {};
```

@@@ js-06 | сравнение, типы
Разница между `==` и `===`? Чему равно `NaN === NaN`?
???
`===` сравнивает без приведения типов, `==` приводит: `'1' == 1`, `0 == ''`, `null == undefined` — всё `true`. Используй `===`. Исключение — `x == null` как короткая проверка на `null`/`undefined`.

`NaN === NaN` → `false`. Проверка: `Number.isNaN(x)` или `Object.is(x, NaN)`. А ещё `Object.is(0, -0)` → `false`.

@@@ js-07 | прототипы, ооп
Как работает прототипное наследование?
???
У каждого объекта есть скрытая ссылка `[[Prototype]]` (`Object.getPrototypeOf(obj)`). При чтении свойства JS идёт по **цепочке прототипов**, пока не найдёт его или не дойдёт до `null`.

`class` — синтаксический сахар над прототипами: методы лежат в `Class.prototype`.

```js
const animal = { eat() { return "ест"; } };
const cat = Object.create(animal);
cat.eat(); // "ест" — найдено в прототипе
```

@@@ js-08 | промисы, async
Чем отличаются `Promise.all`, `allSettled`, `race` и `any`?
???
- `all` — ждёт все; падает при **первом** reject.
- `allSettled` — ждёт все и никогда не падает: `[{ status, value | reason }]`.
- `race` — результат первого завершившегося (успех или ошибка).
- `any` — первый **успешный**; если упали все — `AggregateError`.

`all` — для независимых запросов, которые нужны все. `allSettled` — когда устраивает частичный успех.

@@@ js-09 | async, промисы
Как обрабатывать ошибки в async/await? Что будет, если забыть `await`?
???
`try/catch` вокруг `await` или `.catch()` у промиса. Без `await` функция сразу вернёт промис, ошибка уйдёт в unhandled rejection, и `try/catch` её не поймает.

Последовательно или параллельно:

```js
// медленно: запросы по очереди
const a = await getA();
const b = await getB();

// быстро: параллельно
const [a2, b2] = await Promise.all([getA(), getB()]);
```

@@@ js-10 | debounce, задачи
Чем debounce отличается от throttle? Напиши debounce.
???
**debounce** — вызвать один раз после паузы (поиск при вводе). **throttle** — не чаще раза в N мс (scroll, resize).

```ts
function debounce<A extends unknown[]>(fn: (...args: A) => void, ms: number) {
  let t: ReturnType<typeof setTimeout>;
  return (...args: A) => {
    clearTimeout(t);
    t = setTimeout(() => fn(...args), ms);
  };
}
```

@@@ js-11 | this, функции
`call`, `apply`, `bind` — в чём разница?
???
Все три задают `this`:

- `call(ctx, a, b)` — вызывает сразу, аргументы списком;
- `apply(ctx, [a, b])` — вызывает сразу, аргументы массивом;
- `bind(ctx, a)` — **возвращает новую функцию** с привязанным контекстом (и частично применёнными аргументами).

Повторный `bind` контекст не меняет. На стрелочные функции не действуют.

@@@ js-12 | объекты, копирование
Поверхностное и глубокое копирование. Как скопировать объект глубоко?
???
Spread `{...obj}` и `Object.assign` копируют только верхний уровень — вложенные объекты остаются общими.

Глубоко: `structuredClone(obj)` — поддерживает `Date`, `Map`, `Set`, циклические ссылки; не копирует функции и DOM-узлы.

`JSON.parse(JSON.stringify(obj))` теряет `undefined` и функции, а `Date` превращает в строку.

@@@ js-13 | коллекции
`Map` против `Object`, `Set`, `WeakMap` — когда что?
???
- **Map** — ключи любого типа, порядок вставки, есть `size`, быстрые частые добавления и удаления.
- **Object** — записи с заранее известными строковыми ключами.
- **Set** — уникальные значения: `[...new Set(arr)]`.
- **WeakMap / WeakSet** — ключи только объекты, держатся слабо и не мешают сборке мусора. Подходят для кэша и метаданных к объектам, не итерируются.

@@@ js-14 | dom, события
Что такое всплытие и делегирование событий?
???
Событие проходит фазы: **погружение** (от `window` к цели) → цель → **всплытие** (обратно вверх).

Делегирование — один обработчик на родителе вместо сотни на детях:

```js
list.addEventListener("click", (e) => {
  const item = e.target.closest("li");
  if (item) select(item.dataset.id);
});
```

`e.target` — где кликнули, `e.currentTarget` — где висит обработчик. `stopPropagation()` останавливает всплытие.

@@@ js-15 | массивы, иммутабельность
Какие методы массива мутируют исходный массив? Какие есть иммутабельные аналоги?
???
Мутируют: `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`.

ES2023 добавил копирующие версии: `toSorted()`, `toReversed()`, `toSpliced()`, `with(i, v)`. В React и Redux состояние мутировать нельзя — используй их или spread.

Ловушка: `[10, 9, 1].sort()` → `[1, 10, 9]`, потому что сортирует как строки. Нужно `sort((a, b) => a - b)`.

@@@ js-16 | типы
Какие типы данных есть в JS? Что вернёт `typeof null`?
???
7 примитивов: `string`, `number`, `bigint`, `boolean`, `undefined`, `symbol`, `null` — и `object` (включая массивы и функции). Примитивы передаются по значению, объекты — по ссылке.

`typeof null === "object"` — историческая ошибка языка. `typeof function () {}` → `"function"`. Массив проверяй через `Array.isArray`.

@@@ js-17 | модули
Чем ES-модули отличаются от CommonJS?
???
**ESM** (`import`/`export`) — статические: импорты известны до выполнения, поэтому работают tree-shaking и top-level `await`. Экспорт — **живая привязка**, загрузка асинхронная.

**CommonJS** (`require`/`module.exports`) — динамический и синхронный, экспортирует копию значения.

В браузере и современных бандлерах стандарт — ESM.

@@@ js-18 | операторы
Что делают `?.` и `??`? Чем `??` отличается от `||`?
???
`a?.b?.()` — безопасный доступ: если слева `null` или `undefined`, вся цепочка сразу вернёт `undefined` без ошибки. Работает и для вызова `fn?.()`, и для индекса `arr?.[0]`.

`??` подставляет значение только для `null`/`undefined`, а `||` — для **любого** falsy (`0`, `''`, `false`, `NaN`):

```js
const count = 0;
count || 10; // 10 — неожиданно
count ?? 10; // 0

settings.volume ??= 50; // присвоить, только если там null/undefined
```

Ловушка: `?.` не стоит ставить везде подряд — он маскирует ошибки там, где значение обязано быть. Смешивать `??` с `||` или `&&` без скобок нельзя — это синтаксическая ошибка.

@@@ js-19 | память
Как работает сборщик мусора и откуда берутся утечки памяти?
???
Алгоритм **mark-and-sweep**: от корней (глобальный объект, стек) помечается всё достижимое, остальное удаляется.

Утечка — объект, который остался достижимым по ошибке:

- забытые таймеры и подписки (`addEventListener` без удаления);
- замыкания на большие данные;
- растущие глобальные кэши;
- ссылки на удалённые DOM-узлы.

В React — эффекты без cleanup.

@@@ js-20 | браузер, производительность
Что происходит, когда браузер рисует страницу (critical rendering path)?
???
HTML → **DOM**, CSS → **CSSOM** → Render Tree → **Layout** (геометрия) → **Paint** (пиксели) → **Composite** (слои).

- изменение `width` или `top` → layout (дорого);
- `color` → paint;
- `transform` и `opacity` → только composite, на GPU. Поэтому анимируют их.

Чтение `offsetHeight` сразу после записи стилей вызывает принудительный layout (layout thrashing).

@@@ js-21 | сеть, async
Как отменить fetch-запрос?
???
Через `AbortController`:

```ts
const controller = new AbortController();

fetch(url, { signal: controller.signal }).catch((e) => {
  if (e.name === "AbortError") return;
  throw e;
});

controller.abort();
```

В React отменяют в cleanup эффекта, чтобы не было гонок при смене параметров. Для таймаута: `AbortSignal.timeout(5000)`.

@@@ js-22 | сеть, безопасность
Что такое CORS и почему возникает ошибка?
???
Браузер блокирует ответы на запросы к другому **origin** (протокол + домен + порт), если сервер не разрешил это заголовком `Access-Control-Allow-Origin`.

Для «непростых» запросов (PUT, JSON, свои заголовки) сначала уходит preflight `OPTIONS`.

Чинится на **сервере** или через прокси, не на клиенте. Это защита браузера: curl и запросы сервер → сервер CORS не касается.

@@@ js-23 | браузер, хранилища
`cookie`, `localStorage`, `sessionStorage`, IndexedDB — в чём разница?
???
- **cookie** — ~4 КБ, уходит на сервер с каждым запросом. Может быть `HttpOnly` — тогда недоступна JS (так хранят сессию).
- **localStorage** — ~5 МБ, синхронный, бессрочный, только строки.
- **sessionStorage** — то же, но живёт до закрытия вкладки.
- **IndexedDB** — асинхронная БД на сотни МБ: объекты, индексы, транзакции.

Это приложение хранит карточки в IndexedDB.

@@@ js-24 | иммутабельность, функции
Что такое чистая функция и иммутабельность? Почему это важно в React?
???
**Чистая функция** — результат зависит только от аргументов, побочных эффектов нет. **Иммутабельность** — данные не меняем, а создаём новые.

React и Redux сравнивают состояние **по ссылке** (`Object.is`). Мутация не меняет ссылку → ререндера не будет:

```js
setItems([...items, x]);       // ✓ новый массив
items.push(x); setItems(items); // ✗ та же ссылка
```

@@@ js-25 | безопасность
Что такое XSS и как от него защититься?
???
Внедрение чужого скрипта через пользовательские данные.

React экранирует текст в JSX, но опасны `dangerouslySetInnerHTML`, `href="javascript:…"`, `innerHTML` и `eval`.

Защита: не вставлять сырой HTML (или чистить через DOMPurify), Content-Security-Policy, токены в `HttpOnly` cookie, а не в localStorage.

@@@ js-26 | итераторы, генераторы
Что такое итераторы и генераторы?
???
**Итератор** — объект с методом `next()`, который возвращает `{ value, done }`. Объект **итерируемый**, если у него есть метод `[Symbol.iterator]`: тогда работают `for...of`, spread и деструктуризация.

**Генератор** (`function*`) — функция, которая умеет приостанавливаться на `yield` и продолжать с того же места. Она возвращает итератор.

```js
function* ids() {
  let id = 1;
  while (true) yield id++; // бесконечная, но ленивая последовательность
}
const gen = ids();
gen.next().value; // 1
gen.next().value; // 2

const range = {
  from: 1,
  to: 3,
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i;
  },
};
[...range]; // [1, 2, 3]
```

@@@ js-27 | proxy, метапрограммирование
Что такое `Proxy` и где он применяется?
???
Обёртка над объектом, которая перехватывает операции: чтение, запись, удаление, `in` и другие. `Reflect` выполняет операцию по умолчанию.

```js
const user = { name: "Ann", age: 30 };
const watched = new Proxy(user, {
  set(target, key, value) {
    console.log(`${String(key)}: ${target[key]} → ${value}`);
    return Reflect.set(target, key, value);
  },
});
watched.age = 31; // "age: 30 → 31"
```

На Proxy построены реактивность Vue 3, черновики Immer (их использует Redux Toolkit), MobX. Также — валидация, логирование, значения по умолчанию.

@@@ js-28 | циклы, ловушка
Чем `for...in` отличается от `for...of`?
???
- `for...in` перебирает **ключи** (строки) объекта, включая унаследованные перечисляемые свойства.
- `for...of` перебирает **значения** итерируемого объекта: массива, строки, `Map`, `Set`.

```js
const arr = ["a", "b"];
arr.extra = "!";

for (const i in arr) console.log(i); // "0", "1", "extra"
for (const v of arr) console.log(v); // "a", "b"
```

Для массивов — `for...of` (или методы массива). Для объектов — `Object.keys/values/entries` + `for...of`.

@@@ js-29 | массивы, группировка
Как сгруппировать массив объектов по полю?
???
Современный способ (ES2024) — `Object.groupBy`:

```js
const people = [
  { name: "Ann", dept: "dev" },
  { name: "Bob", dept: "qa" },
  { name: "Kim", dept: "dev" },
];

Object.groupBy(people, (p) => p.dept);
// { dev: [Ann, Kim], qa: [Bob] } — объект без прототипа

Map.groupBy(people, (p) => p.dept); // то же, но в Map
```

Классика для собеса — через `reduce`:

```js
const byDept = people.reduce((acc, p) => {
  (acc[p.dept] ??= []).push(p.name);
  return acc;
}, {});
// { dev: ["Ann", "Kim"], qa: ["Bob"] }
```

@@@ js-30 | symbol, типы
Что такое `Symbol` и где он применяется?
???
`Symbol()` — примитив, гарантированно уникальный: `Symbol("id") !== Symbol("id")`. Описание в скобках нужно только для отладки.

Зачем нужен:

- **Ключи без конфликтов.** Символьное свойство не пересечётся с чужими полями и не видно в `for...in`, `Object.keys` и `JSON.stringify`.
- **Встроенные (well-known) символы** настраивают поведение объекта: `Symbol.iterator` делает его перебираемым, `Symbol.toPrimitive` управляет приведением к примитиву, `Symbol.asyncIterator` — для `for await`.

```js
const range = {
  from: 1,
  to: 3,
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i;
  },
};
[...range]; // [1, 2, 3]
```

`Symbol.for("app.key")` берёт символ из глобального реестра: один и тот же для всех вызовов с этим ключом.

@@@ js-31 | объекты, дескрипторы
Что такое дескрипторы свойств, геттеры и сеттеры?
???
У каждого свойства есть флаги: `writable` (можно менять), `enumerable` (видно в `Object.keys` и `for...in`), `configurable` (можно удалить и перенастроить).

```js
const user = {};
Object.defineProperty(user, "id", { value: 1, writable: false, enumerable: true });
user.id = 2;   // молча игнорируется, в строгом режиме — TypeError
```

У `defineProperty` все флаги по умолчанию `false`, у обычного присваивания — `true`.

Геттер и сеттер — вычисляемое свойство, которое выглядит как обычное поле:

```js
const temp = {
  celsius: 20,
  get fahrenheit() { return this.celsius * 1.8 + 32; },
  set fahrenheit(f) { this.celsius = (f - 32) / 1.8; },
};
temp.fahrenheit = 212; // temp.celsius === 100
```

Посмотреть флаги: `Object.getOwnPropertyDescriptor(obj, "key")`.

@@@ js-32 | объекты, иммутабельность
Чем отличаются `Object.freeze`, `Object.seal` и `Object.preventExtensions`?
???
Это три ступени защиты объекта, от мягкой к строгой:

- `preventExtensions` — нельзя **добавлять** новые свойства; удалять и менять можно;
- `seal` — нельзя добавлять и **удалять**; менять значения можно;
- `freeze` — нельзя ничего: ни добавлять, ни удалять, ни **менять**.

```js
const user = Object.seal({ name: "Аня" });
user.name = "Боб"; // ок
delete user.name;  // не сработает
user.age = 20;     // не сработает
```

Важные детали:

- Все три **поверхностные**: `Object.freeze(config)` не замораживает `config.db` — вложенный объект можно менять. Для глубокой заморозки нужен рекурсивный обход.
- Нарушение в обычном режиме молча игнорируется, а в строгом (модули, классы) бросает `TypeError`.
- `const` и `freeze` — разные вещи: `const` запрещает переприсвоить переменную, `freeze` — менять сам объект.

В TypeScript для того же на уровне типов есть `Readonly<T>` и `as const`, но они работают только при компиляции.

@@@ js-33 | классы, прототипы
Что такое классы в JS под капотом?
???
Синтаксис поверх прототипов: методы класса попадают в `Class.prototype`, а экземпляр ссылается на него через `[[Prototype]]`.

```js
class Animal {
  #secret = 42;           // приватное поле, недоступно снаружи
  static count = 0;       // поле самого класса, а не экземпляра
  constructor(name) { this.name = name; }
  speak() { return `${this.name} издаёт звук`; }
}

class Dog extends Animal {
  speak() { return `${super.speak()}: гав`; }
}

typeof Animal;                                       // "function"
Object.getPrototypeOf(Dog.prototype) === Animal.prototype; // true
```

Отличия от функций-конструкторов: класс нельзя вызвать без `new`, тело класса всегда в строгом режиме, методы не перечисляются в `for...in`, а в наследнике нужно вызвать `super()` до обращения к `this`.

@@@ js-34 | функции, this
Чем стрелочная функция отличается от обычной?
???
- **Нет своего `this`** — берётся из окружения, где стрелка создана. `call`, `apply` и `bind` его не меняют.
- **Нет `arguments`** — используй rest-параметры `(...args)`.
- **Нельзя вызвать с `new`** и нет `prototype`.
- Не может быть генератором.

```js
class Timer {
  seconds = 0;
  start() {
    setInterval(() => this.seconds++, 1000); // this — экземпляр
    // с function () { this.seconds++ } this был бы потерян
  }
}
```

Когда стрелка **не** подходит: методы объекта, которым нужен `this` объекта (`{ getName: () => this.name }` вернёт не то), и обработчики, где нужен `this` как элемент.

@@@ js-35 | деструктуризация, ловушка
Когда срабатывают значения по умолчанию в деструктуризации и параметрах?
???
Только когда значение строго `undefined`. `null`, `0` и `""` дефолт **не** заменяет:

```js
const { limit = 10 } = { limit: null };
limit; // null

function greet(name = "гость") { return name; }
greet(undefined); // "гость"
greet(null);      // null
```

Полезные приёмы:

```js
const { a: { b } = {} } = obj;          // вложенный дефолт, если obj.a нет
const { id, ...rest } = user;           // rest — объект без id
const [first, , third] = list;          // пропуск элемента
function f({ page = 1, size = 20 } = {}) {} // можно вызвать f() без аргументов
```

Если `null` тоже нужно заменить, используй `??`: `const limit = options.limit ?? 10`.

@@@ js-36 | функции, каррирование
Что такое каррирование? Напиши `curry`.
???
Превращение функции от нескольких аргументов в цепочку функций, каждая из которых принимает часть аргументов: `sum(1, 2, 3)` → `sum(1)(2)(3)`.

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) return fn.apply(this, args);
    return (...next) => curried.apply(this, [...args, ...next]);
  };
}

const sum = curry((a, b, c) => a + b + c);
sum(1)(2)(3); // 6
sum(1, 2)(3); // 6
```

`fn.length` — число объявленных параметров (без rest и параметров со значениями по умолчанию).

Зачем на практике: частичное применение и заготовки функций — `const logError = log("error")`, `const byId = prop("id")`. В React похожий приём — обработчик, который возвращает обработчик: `onClick={select(id)}`.

@@@ js-37 | функции, кэш
Что такое мемоизация? Напиши `memoize`.
???
Кэширование результата функции по аргументам: повторный вызов с теми же аргументами возвращает готовый ответ, не пересчитывая. Подходит только для **чистых** функций.

```js
function memoize(fn) {
  const cache = new Map();
  return (...args) => {
    const key = JSON.stringify(args);
    if (!cache.has(key)) cache.set(key, fn(...args));
    return cache.get(key);
  };
}

const slowSquare = (n) => n * n;
const fastSquare = memoize(slowSquare);
```

Подводные камни, которые спрашивают на собесе:

- `JSON.stringify` плохо работает с функциями, `Map`, циклическими ссылками; для одного аргумента-объекта лучше `WeakMap` с объектом как ключом.
- Кэш растёт бесконечно — нужен лимит (LRU) или сброс.
- Асинхронную функцию тоже можно мемоизировать — кэшируется промис, и параллельные вызовы получат один запрос.

@@@ js-38 | промисы, задача
Напиши свой `Promise.all`.
???
```js
function promiseAll(items) {
  return new Promise((resolve, reject) => {
    const list = Array.from(items);
    const results = new Array(list.length);
    let left = list.length;
    if (left === 0) return resolve(results);

    list.forEach((item, i) => {
      Promise.resolve(item).then((value) => {
        results[i] = value;
        if (--left === 0) resolve(results);
      }, reject);
    });
  });
}
```

На что смотрят:

- результаты кладутся **по индексу**, а не в порядке завершения;
- `Promise.resolve(item)` позволяет передавать и обычные значения;
- первая ошибка сразу отклоняет общий промис (остальные запросы при этом не отменяются);
- пустой массив — сразу `[]`.

@@@ js-39 | функции, полифил
Напиши полифил `Function.prototype.bind`.
???
`bind` возвращает новую функцию с привязанным `this` и частью аргументов:

```js
Function.prototype.myBind = function (context, ...bound) {
  const fn = this;
  return function (...args) {
    return fn.apply(context, [...bound, ...args]);
  };
};

const user = { name: "Аня" };
function hello(greeting, mark) { return `${greeting}, ${this.name}${mark}`; }

const hi = hello.myBind(user, "Привет");
hi("!"); // "Привет, Аня!"
```

Чем настоящий `bind` сложнее: если связанную функцию вызвать с `new`, привязанный `this` игнорируется и создаётся новый объект. Повторный `bind` уже связанной функции `this` не меняет.

@@@ js-40 | промисы, таймауты
Как ограничить время ожидания промиса или запроса?
???
Для любого промиса — гонка с таймером:

```js
const withTimeout = (promise, ms) => {
  let timer;
  const timeout = new Promise((_, reject) => {
    timer = setTimeout(() => reject(new Error("Timeout")), ms);
  });
  return Promise.race([promise, timeout]).finally(() => clearTimeout(timer));
};
```

Минус: исходная операция продолжает выполняться, мы просто перестаём её ждать.

Для `fetch` есть способ лучше — он действительно отменяет запрос:

```js
const res = await fetch(url, { signal: AbortSignal.timeout(5000) });
// при таймауте — ошибка с name === "TimeoutError"
```

Совместить ручную отмену и таймаут: `AbortSignal.any([controller.signal, AbortSignal.timeout(5000)])`.

@@@ js-41 | fetch, ловушка
Почему `fetch` не бросает ошибку на 404 или 500?
???
`fetch` отклоняет промис только при **сетевой** ошибке: нет сети, CORS, DNS, отмена. Ответ 404 или 500 — это успешно полученный HTTP-ответ, промис выполняется, а `res.ok` равен `false`.

```js
async function getJson(url) {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}
```

Ещё отличия от axios:

- тело нужно прочитать вручную: `res.json()`, `res.text()` — и только один раз;
- нет встроенного таймаута (используют `AbortSignal.timeout`);
- для отправки JSON нужно самому сделать `JSON.stringify` и указать заголовок `Content-Type: application/json`;
- cookies на другой домен уходят только с `credentials: "include"`.

@@@ js-42 | dom, события
Чем отличаются `preventDefault`, `stopPropagation` и фаза перехвата?
???
- `preventDefault()` отменяет **действие браузера по умолчанию**: переход по ссылке, отправку формы, прокрутку. Событие продолжает всплывать.
- `stopPropagation()` останавливает **распространение** события к другим элементам. Действие браузера при этом выполнится.
- `stopImmediatePropagation()` — ещё и не даёт сработать остальным обработчикам на этом же элементе.

Фаза перехвата (capturing) идёт **до** всплытия, от `window` вниз к цели:

```js
document.addEventListener("click", log, { capture: true }); // сработает первым
```

Полезные опции: `{ once: true }` — обработчик удалится после первого вызова; `{ passive: true }` — обещание не вызывать `preventDefault`, что ускоряет прокрутку на `touchmove` и `wheel`.

Ловушка: `stopPropagation` ломает делегирование и аналитику, которые слушают события выше, — используй его осознанно.

@@@ js-43 | браузер, загрузка
Чем отличаются `<script>`, `async` и `defer`?
???
- **Обычный `<script>`** блокирует разбор HTML: браузер останавливается, скачивает и выполняет скрипт, потом продолжает.
- **`async`** скачивается параллельно и выполняется **сразу, как загрузится**, прерывая разбор. Порядок между скриптами не гарантирован. Подходит для независимых скриптов: аналитика, реклама.
- **`defer`** скачивается параллельно, выполняется **после разбора HTML**, перед `DOMContentLoaded`, строго в порядке подключения. Подходит для основного кода приложения.

```html
<script src="analytics.js" async></script>
<script src="vendor.js" defer></script>
<script src="app.js" defer></script>
```

`<script type="module">` по умолчанию ведёт себя как `defer`. Старый совет «ставь скрипты в конец `<body>`» решал ту же проблему до появления `defer`.

@@@ js-44 | http, кэширование
Как работает HTTP-кэширование: `Cache-Control`, `ETag`?
???
Сервер говорит браузеру, сколько можно хранить ответ, через заголовок `Cache-Control`:

- `max-age=31536000, immutable` — хранить год и не перепроверять. Так отдают статику с хешем в имени (`app.3f9a.js`): новая версия — новое имя файла.
- `no-cache` — хранить можно, но перед использованием **обязательно** спросить сервер. Так отдают HTML.
- `no-store` — не хранить вообще (личные данные).
- `private` / `public` — можно ли кэшировать на CDN и прокси.

Перепроверка (revalidation): сервер присылает `ETag: "abc"` (отпечаток содержимого). Браузер в следующий раз отправит `If-None-Match: "abc"`, и если ничего не изменилось, сервер ответит `304 Not Modified` без тела — экономия трафика.

`stale-while-revalidate=60` разрешает показать устаревший ответ и обновить его в фоне.

@@@ js-45 | безопасность, авторизация
Где хранить токен авторизации: `localStorage` или cookie?
???
**`localStorage`** доступен любому JS на странице. Если на сайте найдётся XSS, скрипт злоумышленника прочитает токен и отправит себе.

**Cookie с флагами** безопаснее:

```
Set-Cookie: session=…; HttpOnly; Secure; SameSite=Lax; Path=/
```

- `HttpOnly` — JS не может прочитать cookie, украсть её через XSS нельзя;
- `Secure` — только по HTTPS;
- `SameSite=Lax` — не отправляется с запросами с чужих сайтов (кроме переходов по ссылке), это базовая защита от CSRF.

Частая схема с JWT: короткоживущий access-токен в памяти приложения и долгоживущий refresh-токен в `HttpOnly` cookie. Важно: XSS всё равно опасен — скрипт может слать запросы от имени пользователя, просто не унесёт токен с собой.

@@@ js-46 | безопасность, csrf
Что такое CSRF и как от него защищаются?
???
Cross-Site Request Forgery — чужой сайт заставляет браузер пользователя отправить запрос на ваш сайт. Браузер автоматически приложит cookie, и сервер решит, что запрос сделал сам пользователь.

```html
<!-- на сайте злоумышленника -->
<form action="https://bank.example/transfer" method="POST">
  <input name="to" value="hacker" />
</form>
<script>document.forms[0].submit()</script>
```

Защита:

- `SameSite=Lax` или `Strict` у сессионной cookie — главная защита в современных браузерах;
- CSRF-токен: случайное значение в форме, которое сервер сверяет с сессией;
- проверка заголовков `Origin` / `Referer`;
- не менять данные GET-запросами.

Если токен передаётся в заголовке `Authorization`, а не в cookie, классический CSRF не работает — браузер не подставляет этот заголовок сам. Server Actions в Next.js сверяют `Origin` с `Host` автоматически.

@@@ js-47 | безопасность, csp
Что такое Content Security Policy?
???
Заголовок ответа, который говорит браузеру, откуда странице **разрешено** загружать скрипты, стили, картинки и куда отправлять запросы. Даже если злоумышленник внедрит `<script>`, браузер его не выполнит.

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-r4nd0m';
  img-src 'self' https://cdn.example.com;
  connect-src 'self' https://api.example.com;
  object-src 'none';
  frame-ancestors 'none'
```

- `'self'` — только свой домен;
- `nonce` — разрешает конкретные inline-скрипты с этим одноразовым значением, без небезопасного `'unsafe-inline'`;
- `frame-ancestors 'none'` — запрет встраивать сайт в iframe (защита от кликджекинга).

Внедряют постепенно: сначала `Content-Security-Policy-Report-Only` — нарушения только логируются, ничего не ломается. CSP — второй рубеж: экранировать данные всё равно нужно.

@@@ js-48 | сеть, realtime
Как получать обновления с сервера в реальном времени: polling, SSE, WebSocket?
???
- **Polling** — запрос раз в N секунд. Просто и работает везде, но много пустых запросов и задержка до N секунд.
- **Long polling** — сервер держит запрос открытым, пока не появятся данные. Меньше пустых ответов, но сложнее на сервере.
- **SSE (Server-Sent Events)** — одно HTTP-соединение, по которому сервер шлёт события **в одну сторону**. Автопереподключение из коробки. Хорошо для уведомлений, ленты, стриминга ответа ИИ.
- **WebSocket** — постоянное **двустороннее** соединение. Для чатов, совместного редактирования, игр. Переподключение и heartbeat придётся писать самому.

```js
const events = new EventSource("/api/notifications");
events.onmessage = (e) => show(JSON.parse(e.data));
```

Правило выбора: если клиенту нужно только получать — SSE; если обе стороны часто шлют сообщения — WebSocket.

@@@ js-49 | браузер, производительность
Что такое Web Workers и когда они нужны?
???
JavaScript в браузере выполняется в одном главном потоке — там же, где отрисовка и обработка кликов. Тяжёлое вычисление на 2 секунды заморозит интерфейс на 2 секунды.

Web Worker — отдельный поток для вычислений. У него нет доступа к DOM, общение — сообщениями:

```js
// main.js
const worker = new Worker(new URL("./worker.js", import.meta.url), { type: "module" });
worker.postMessage(bigArray);
worker.onmessage = (e) => render(e.data);

// worker.js
self.onmessage = (e) => self.postMessage(heavySort(e.data));
```

Когда нужны: парсинг больших файлов (CSV, Excel), обработка изображений, шифрование, поиск по большому массиву.

Данные при передаче **копируются** (structured clone). Большие бинарные буферы можно передать без копирования — как transferable-объекты.

@@@ js-50 | dom, observer
Что такое `IntersectionObserver` и где он нужен?
???
API, которое сообщает, когда элемент появляется в области видимости или уходит из неё. Работает асинхронно и не нагружает главный поток, в отличие от обработчика `scroll` с `getBoundingClientRect`.

```js
const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) loadMore();
    });
  },
  { rootMargin: "200px" }, // сработать за 200px до появления
);
observer.observe(sentinel);
// при размонтировании: observer.disconnect()
```

Где применяют: бесконечная лента (следим за элементом в конце списка), ленивая загрузка картинок и тяжёлых блоков, анимации при прокрутке, учёт просмотров рекламы.

Для картинок обычно хватает встроенного `<img loading="lazy">`. Родственники: `ResizeObserver` (изменение размеров элемента) и `MutationObserver` (изменения DOM).

@@@ js-51 | intl, форматирование
Как правильно форматировать числа, валюту и даты?
???
Встроенным API `Intl` — он знает правила локали, и не нужно склеивать строки вручную:

```js
new Intl.NumberFormat("ru-RU", { style: "currency", currency: "RUB" }).format(1234.5);
// "1 234,50 ₽"

new Intl.DateTimeFormat("ru-RU", { day: "numeric", month: "long" }).format(new Date());
// "31 октября"

new Intl.RelativeTimeFormat("ru", { numeric: "auto" }).format(-1, "day");
// "вчера"

new Intl.PluralRules("ru-RU").select(5); // "many" — для «5 карточек»
```

Короткие варианты: `num.toLocaleString("ru-RU")` и `date.toLocaleDateString("ru-RU")`.

Совет: создание форматтера — дорогая операция. В списке на тысячи строк создай его один раз снаружи и вызывай `.format()`. И помни, что результат зависит от локали: на сервере и клиенте она может отличаться, что даст hydration mismatch.
