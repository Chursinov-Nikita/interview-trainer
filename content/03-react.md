@@@ react-01 | reconciliation, key
Как работает reconciliation и зачем нужен `key`?
???
При ререндере React сравнивает новое дерево элементов со старым:

- другой тип элемента → поддерево пересоздаётся;
- тот же тип → обновляются пропсы.

В списках `key` сопоставляет элементы между рендерами. Индекс в роли key ломается при вставке, удалении и сортировке: состояние (инпуты, фокус) «переезжает» на чужие элементы. Key должен быть стабильным и уникальным среди соседей.

@@@ react-02 | key, state
Как сбросить состояние компонента при смене пропса?
???
Сменить `key` — React размонтирует старый экземпляр и создаст новый с чистым состоянием:

```tsx
<ProfileForm key={userId} userId={userId} />
```

Это лучше, чем `useEffect(() => setForm(initial), [userId])`: эффект сначала покажет устаревшие данные, а потом перерисует.

@@@ react-03 | рендер
Из каких фаз состоит обновление в React? Что вызывает ререндер?
???
- **Render** — вызов компонентов и построение нового дерева. Чистая фаза, в concurrent-режиме может прерываться.
- **Commit** — изменения применяются к DOM, затем layout-эффекты, а после отрисовки — обычные эффекты.

Ререндер компонента вызывают: изменение его state, **ререндер родителя** (даже если пропсы те же!), изменение используемого контекста.

@@@ react-04 | хуки, эффекты
`useEffect` против `useLayoutEffect`?
???
`useEffect` выполняется **после** отрисовки и не блокирует браузер — для запросов, подписок, логирования.

`useLayoutEffect` — синхронно после изменения DOM, но **до** отрисовки: для измерения размеров и позиционирования (тултипы), чтобы не было мигания.

Злоупотребление `useLayoutEffect` тормозит отрисовку. На сервере он не выполняется.

@@@ react-05 | хуки, замыкания
Что такое устаревшее замыкание (stale closure) в хуках?
???
Колбэк захватил значения из рендера, в котором был создан:

```tsx
const [count, setCount] = useState(0);

useEffect(() => {
  const id = setInterval(() => setCount(count + 1), 1000); // count всегда 0
  return () => clearInterval(id);
}, []);
```

Решения: функциональное обновление `setCount((c) => c + 1)`, честные зависимости, `useRef` с последним значением, `useEffectEvent`.

@@@ react-06 | производительность, memo
Когда нужны `useMemo`, `useCallback` и `React.memo`?
???
- `React.memo(Component)` пропускает ререндер, если пропсы поверхностно равны.
- `useCallback` и `useMemo` сохраняют ссылку на функцию или значение между рендерами.

Ссылки нужно сохранять, чтобы memo-компонент не перерисовывался, чтобы эффекты не перезапускались из-за зависимостей и чтобы не пересчитывать дорогие вычисления.

Мемоизация не бесплатна, без замеров часто бесполезна. React Compiler делает её автоматически — этот проект собран с ним.

@@@ react-07 | производительность, compiler
Что делает React Compiler?
???
Плагин сборки: анализирует компоненты и **автоматически мемоизирует** значения, колбэки и JSX вместо ручных `useMemo`, `useCallback`, `memo`.

Требует соблюдать правила React: чистые компоненты, никаких мутаций пропсов и state, хуки по правилам. Код, нарушающий правила, компилятор пропускает без оптимизации.

@@@ react-08 | хуки
Правила хуков. Почему они такие?
???
Хуки вызываются только на верхнем уровне компонента или своего хука — не в условиях, циклах и не после раннего `return`.

React хранит состояние хуков **по порядку вызова** в списке у fiber-узла. Если порядок изменится между рендерами, состояния перепутаются.

Исключение — `use()`: его можно вызывать в условиях.

@@@ react-09 | хуки, ref
Для чего нужен `useRef`, кроме доступа к DOM?
???
Хранить изменяемое значение между рендерами **без ререндера**: id таймера, предыдущее значение, флаг, последний колбэк.

Изменение `ref.current` не вызывает перерисовку, поэтому в ref нельзя держать то, что показываешь на экране. Не читай и не пиши `ref.current` во время рендера (кроме ленивой инициализации).

@@@ react-10 | формы
Контролируемые и неконтролируемые компоненты?
???
**Контролируемый** — значение в state React (`value` + `onChange`). Удобно валидировать и преобразовывать на лету.

**Неконтролируемый** — значение хранит DOM (`defaultValue`, чтение через ref или `FormData`). Меньше ререндеров.

React 19 с `<form action={fn}>` снова сделал неконтролируемые формы удобными. Частая ошибка — `value` меняется с `undefined` на строку, и React предупреждает о смене режима.

@@@ react-11 | state, антипаттерн
Почему не стоит копировать пропсы в state и синхронизировать их через `useEffect`?
???
Это лишний рендер с устаревшими данными и источник рассинхронизации. Вычисляй прямо в рендере:

```tsx
// ✗
const [full, setFull] = useState("");
useEffect(() => setFull(`${first} ${last}`), [first, last]);

// ✓
const full = `${first} ${last}`;
```

Дорогое вычисление — в `useMemo`. Нужно сбросить state при смене пропса — меняй `key`.

@@@ react-12 | context, производительность
Какая проблема производительности у Context и как её решить?
???
Все потребители контекста ререндерятся при **любом** изменении `value`. Если `value` — новый объект на каждом рендере провайдера, они ререндерятся всегда.

Решения:

- мемоизировать `value`;
- разделить контексты: данные отдельно от экшенов, частые изменения отдельно;
- держать провайдер ниже в дереве;
- для часто меняющегося глобального состояния взять стор с селекторами (Zustand, Redux).

@@@ react-13 | хуки, state
Когда `useReducer` лучше `useState`?
???
Когда следующее состояние сложно зависит от предыдущего, много связанных полей или переходов: формы, мастер шагов, конечный автомат. Логика переходов живёт в чистой функции — её легко тестировать. `dispatch` стабилен, его можно передавать вниз без `useCallback`.

```ts
type Action = { type: "inc" } | { type: "set"; value: number };

function reducer(state: number, action: Action) {
  switch (action.type) {
    case "inc": return state + 1;
    case "set": return action.value;
  }
}
```

@@@ react-14 | state, batching
Почему state не обновляется сразу после `setState`? Что такое batching?
???
`setState` только планирует ререндер — в текущем замыкании остаётся старое значение. Несколько вызовов объединяются в один рендер (automatic batching — с React 18 везде: в промисах, таймерах, обработчиках).

```tsx
setCount(count + 1);
setCount(count + 1); // итог: +1

setCount((c) => c + 1);
setCount((c) => c + 1); // итог: +2
```

@@@ react-15 | concurrent
Что делают `useTransition` и `useDeferredValue`?
???
Помечают обновление как **несрочное**: React может прервать его рендер ради срочного ввода.

- `useTransition` — когда ты сам вызываешь setState: `startTransition(() => setTab(next))`, плюс флаг `isPending`.
- `useDeferredValue(value)` — когда значение пришло извне: отдаёт «отстающую» копию. Тяжёлый список рендерится по ней, а инпут остаётся отзывчивым.

Это не замена debounce для сетевых запросов.

@@@ react-16 | suspense
Как работает Suspense?
???
Компонент «приостанавливается», пока данные или код не готовы (`use()`, `lazy`, фреймворк), и React показывает ближайший `fallback`. Когда всё готово, рендерит снова.

Suspense позволяет декларативно описывать загрузку и стримить HTML с сервера частями. Связка `useEffect` + fetch с Suspense не работает — нужен `use()` или библиотека с поддержкой.

@@@ react-17 | производительность, lazy
Как разделить бандл на чанки в React?
???
Динамический `import()` + `React.lazy` + `Suspense`:

```tsx
const Chart = lazy(() => import("./Chart"));

<Suspense fallback={<Spinner />}>
  <Chart />
</Suspense>
```

В Next.js — `next/dynamic` и автоматическое разделение по маршрутам. Подходит для тяжёлых и редко видимых частей: модалки, графики, редакторы.

@@@ react-18 | ошибки
Что такое Error Boundary и что он **не** ловит?
???
Классовый компонент с `static getDerivedStateFromError` / `componentDidCatch`: показывает запасной UI при ошибке рендера потомков.

**Не ловит**: ошибки в обработчиках событий, асинхронном коде (таймеры, промисы вне рендера), при SSR и в самом себе.

В Next.js — файл `error.tsx`. Функциональной версии нет, есть библиотека react-error-boundary.

@@@ react-19 | dom, portals
Зачем нужны порталы?
???
`createPortal(children, domNode)` рендерит в другой DOM-узел (обычно `body`), но в дереве React элемент остаётся на месте: работает контекст, а события **всплывают по React-дереву**.

Нужны модалкам, тултипам, тостам — чтобы вырваться из `overflow: hidden` и `z-index` родителя.

@@@ react-20 | strict mode, эффекты
Почему в StrictMode эффекты срабатывают дважды?
???
Только в dev React монтирует, размонтирует и снова монтирует компонент, а рендер вызывает дважды. Так он выявляет нечистые компоненты и эффекты без cleanup.

Если двойной вызов что-то ломает (два запроса, двойная подписка) — значит, нет правильной очистки. В продакшене этого нет.

@@@ react-21 | эффекты, данные
Как правильно загружать данные в `useEffect`? Что такое race condition?
???
Ответы могут прийти не по порядку: ответ на старый запрос перезапишет новый.

```tsx
useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/user/${id}`, { signal: controller.signal })
    .then((r) => r.json())
    .then(setUser)
    .catch(() => {});
  return () => controller.abort();
}, [id]);
```

В продакшене обычно берут TanStack Query или SWR (кэш, дедупликация, повторы) либо серверные компоненты.

@@@ react-22 | хуки, store
Для чего нужен `useSyncExternalStore`?
???
Подписка на внешний источник данных (стор, `matchMedia`, `navigator.onLine`, localStorage) без «разрывов» (tearing) в concurrent-режиме.

```ts
const online = useSyncExternalStore(
  (cb) => {
    addEventListener("online", cb);
    addEventListener("offline", cb);
    return () => {
      removeEventListener("online", cb);
      removeEventListener("offline", cb);
    };
  },
  () => navigator.onLine, // снимок на клиенте
  () => true,             // снимок на сервере
);
```

На нём построены Zustand и react-redux.

@@@ react-23 | rsc, next
Что такое React Server Components? Чем они отличаются от SSR?
???
**Серверные компоненты** выполняются только на сервере: могут быть `async`, ходить в БД, их код не попадает в бандл. **Клиентские** (`"use client"`) интерактивны: state, эффекты, обработчики.

**SSR** — рендер **любых** компонентов в HTML для первой загрузки с последующей гидратацией. RSC — модель, где часть дерева **никогда** не гидратируется.

Серверный компонент может рендерить клиентский. Клиентский импортировать серверный не может — только получить его через `children`.

@@@ react-24 | rsc, next
Что означает `"use client"` и где проводить границу?
???
Директива помечает **точку входа** в клиентский бандл: этот модуль и всё, что он импортирует, становится клиентским.

Держи границу как можно ниже — на интерактивных «листьях» (кнопка, форма), а страницы и разметку оставляй серверными. Пропсы через границу должны сериализоваться: функции передавать нельзя (кроме Server Actions).

@@@ react-25 | ssr, гидратация
Что такое гидратация и откуда берётся hydration mismatch?
???
**Гидратация** — React «оживляет» HTML с сервера: навешивает обработчики, сверяя дерево.

**Mismatch** — клиент отрисовал не то, что сервер: `Date.now()`, `Math.random()`, `window` или `localStorage` в рендере, разная локаль дат, неверная вложенность тегов (`<div>` внутри `<p>`).

Решения: одинаковые данные, браузерные API — в эффекте или в `useSyncExternalStore` с серверным снимком, точечно — `suppressHydrationWarning`.

@@@ react-26 | react 19, формы
Что нового в React 19 для форм (Actions)?
???
- `<form action={fn}>` принимает функцию (в том числе async), которая получает `FormData`.
- `useActionState(action, initial)` → `[state, formAction, isPending]`.
- `useFormStatus()` — статус ближайшей формы, удобно для кнопки.
- `useOptimistic` — показывает результат до ответа сервера и откатывает при ошибке.

В Next.js эти функции могут быть Server Actions (`"use server"`).

@@@ react-27 | react 19, хуки
Что делает хук `use()` в React 19?
???
Читает значение промиса (через Suspense) или контекста. В отличие от других хуков, его можно вызывать в условиях и циклах.

```tsx
function Comments({ promise }: { promise: Promise<Comment[]> }) {
  const comments = use(promise); // приостановит рендер до резолва
  return comments.map((c) => <p key={c.id}>{c.text}</p>);
}
```

Промис нельзя создавать прямо в рендере клиентского компонента — он будет новым каждый раз. Его передают с сервера или берут из кэша.

@@@ react-28 | react 19, ref
Как передать ref в свой компонент в React 19?
???
`ref` теперь обычный проп у функциональных компонентов — `forwardRef` не нужен:

```tsx
function Input({ ref, ...props }: React.ComponentProps<"input">) {
  return <input ref={ref} {...props} />;
}
```

Ref-колбэк теперь может вернуть функцию очистки. `useImperativeHandle` — если наружу нужно отдать не DOM-узел, а свой API (`focus`, `reset`).

@@@ react-29 | хуки
Что такое кастомный хук? Делят ли компоненты его состояние?
???
Функция с именем `use…`, которая вызывает другие хуки. Это способ переиспользовать **логику**, а не состояние: каждый вызов хука получает своё независимое состояние.

Чтобы делить данные, нужно поднять state выше, использовать контекст или внешний стор.

@@@ react-30 | архитектура, композиция
Как избежать prop drilling без контекста?
???
Композицией: передавать готовые элементы через `children` или слоты, чтобы промежуточные компоненты ничего не знали о данных.

```tsx
<Layout sidebar={<UserMenu user={user} />}>
  <Feed user={user} />
</Layout>
```

Ещё помогает перенос состояния ближе к месту использования. Контекст оставь для действительно глобального: тема, пользователь, локаль.

@@@ react-31 | производительность, списки
Как отрендерить список из 10 000 элементов без тормозов?
???
**Виртуализация** — рендерить только видимые строки с небольшим запасом, остальное заменять отступами (TanStack Virtual, react-window).

Плюс стабильные `key`, `memo` для строк, пагинация или бесконечная подгрузка. В простых случаях хватает CSS `content-visibility: auto` — браузер пропускает отрисовку невидимого.

@@@ react-32 | fiber, внутренности
Что такое Fiber?
???
Внутренняя архитектура React с 16-й версии. Каждый компонент — узел fiber: тип, пропсы, state, ссылки на родителя, ребёнка и соседа.

Работа рендера разбита на единицы, которые можно **прерывать, приоритизировать и возобновлять** — на этом построены transitions и Suspense. Деревьев два: текущее и рабочее (double buffering).

@@@ react-33 | хуки, эффекты, react 19
Что такое `useEffectEvent`?
???
(React 19.2) Хук для «событий» внутри эффекта. Функция всегда видит свежие пропсы и state, но **не является зависимостью** эффекта.

```tsx
const onConnected = useEffectEvent(() => showToast(theme));

useEffect(() => {
  const conn = connect(roomId);
  conn.on("connected", onConnected);
  return () => conn.disconnect();
}, [roomId]); // смена theme не переподключает чат
```

@@@ react-34 | эффекты, порядок
В каком порядке вызываются рендер и эффекты у родителя и ребёнка?
???
- **Рендер** — сверху вниз: сначала родитель, потом дети.
- **Эффекты** — снизу вверх: сначала у детей, потом у родителя. Сначала все `useLayoutEffect` (до отрисовки), потом все `useEffect`.

```
parent render → child render →
child layout → parent layout →
child effect → parent effect
```

Поэтому в эффекте родителя DOM детей уже готов, а ref на дочерний элемент заполнен.

@@@ react-35 | рендер, ловушка
Что отрендерит `{count && <Badge />}`, если `count = 0`?
???
Отрендерит **`0`** прямо на странице. `&&` возвращает первый falsy-операнд, а React рисует числа (в отличие от `false`, `null` и `undefined`).

```tsx
{count && <Badge />}       // при 0 покажет «0»
{count > 0 && <Badge />}   // ✓
{!!count && <Badge />}     // ✓
{count ? <Badge /> : null} // ✓
```

В React Native это ещё и падение: текст вне `<Text>`.

@@@ react-36 | state, производительность
Чем отличаются `useState(compute())` и `useState(() => compute())`?
???
Начальное значение нужно только при первом рендере, но выражение в скобках вычисляется **при каждом** рендере:

```tsx
useState(expensive());       // expensive вызывается на каждом рендере
useState(() => expensive()); // только при монтировании — ленивая инициализация
useState(expensive);         // то же самое: передаём саму функцию
```

Это важно для тяжёлых вычислений и чтения из `localStorage`. С `useRef` ленивой формы нет — там инициализируют через `if (ref.current === null)`.

@@@ react-37 | memo, ловушка
Почему `React.memo` не помогает компоненту, который принимает `children`?
???
JSX `<Box><span>hi</span></Box>` при каждом рендере родителя создаёт **новый объект** элемента в `children`. Поверхностное сравнение пропсов видит новую ссылку — memo каждый раз пропускает рендер дальше.

То же с инлайн-объектами и функциями в пропсах: `style={{…}}`, `onClick={() => …}`.

Что делать: мемоизировать передаваемые значения (`useMemo`, `useCallback`) — или вовсе не полагаться на memo, а перестроить дерево (см. «перенос состояния вниз»).

@@@ react-38 | производительность, композиция
Как избежать лишних ререндеров без `memo`?
???
Два приёма композиции:

**1. Перенести состояние вниз** — в компонент, которому оно реально нужно:

```tsx
// ✗ ввод в поле ререндерит всю страницу
function Page() {
  const [q, setQ] = useState("");
  return <><input value={q} onChange={(e) => setQ(e.target.value)} /><HeavyList /></>;
}
// ✓ состояние живёт в SearchBox, HeavyList не трогается
```

**2. Поднять содержимое через `children`**:

```tsx
function ScrollTracker({ children }: { children: React.ReactNode }) {
  const [y, setY] = useState(0);
  // … слушаем скролл и обновляем y
  return <div data-y={y}>{children}</div>;
}
// <ScrollTracker><HeavyList /></ScrollTracker>
```

`children` создан родителем выше, поэтому при изменении `y` React его не перерисовывает.

@@@ react-39 | эффекты, зависимости
Почему эффект с объектом в зависимостях срабатывает на каждом рендере?
???
Зависимости сравниваются через `Object.is`, то есть **по ссылке**. Объект или массив, созданный в рендере, — новый каждый раз:

```tsx
const options = { roomId, serverUrl }; // новый объект на каждом рендере
useEffect(() => {
  const conn = connect(options);
  return () => conn.disconnect();
}, [options]); // переподключение после каждого рендера
```

Решения: класть в зависимости примитивы (`[roomId, serverUrl]`) и создавать объект внутри эффекта, вынести константу из компонента или мемоизировать её через `useMemo`.

@@@ react-40 | хуки, доступность
Для чего нужен `useId`?
???
Генерирует **стабильный уникальный id**, одинаковый на сервере и клиенте — без расхождений при гидратации. Нужен для связки элементов через атрибуты доступности:

```tsx
function Field({ label }: { label: string }) {
  const id = useId();
  return (
    <>
      <label htmlFor={id}>{label}</label>
      <input id={id} aria-describedby={`${id}-hint`} />
      <p id={`${id}-hint`}>Подсказка</p>
    </>
  );
}
```

Не для `key` в списках — ключи берут из данных.

@@@ react-41 | хуки, debounce
Как сделать отложенный поиск (debounce) при вводе?
???
Кастомный хук, который возвращает значение с задержкой:

```tsx
function useDebounce<T>(value: T, ms = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), ms);
    return () => clearTimeout(id); // новое значение сбрасывает таймер
  }, [value, ms]);
  return debounced;
}

const [query, setQuery] = useState("");
const debouncedQuery = useDebounce(query);
// запрос делаем по debouncedQuery
```

`useDeferredValue` — про другое: он не уменьшает число запросов, а откладывает тяжёлый **рендер** ради отзывчивости ввода.

@@@ react-42 | паттерны
Что такое HOC и render props? Почему их почти вытеснили хуки?
???
- **HOC** — функция, которая принимает компонент и возвращает новый с добавленной логикой: `withAuth(Profile)`.
- **Render props** — компонент вызывает функцию из пропса, передавая ей данные: `<Mouse>{(pos) => <Cursor {...pos} />}</Mouse>`.

Оба способа переиспользуют логику, но порождают «ад обёрток» в дереве, конфликты имён пропсов и неявные зависимости. Хуки делают то же короче и явно: `const pos = useMouse()`.

HOC ещё встречаются в библиотеках (`connect` в старом Redux, `observer` в MobX).

@@@ react-43 | тестирование
Как тестировать React-компоненты? Принципы Testing Library.
???
Тестировать **поведение**, а не реализацию: что видит и делает пользователь, а не state и внутренние методы.

```tsx
render(<LoginForm onSubmit={onSubmit} />);
await userEvent.type(screen.getByLabelText("Email"), "a@b.c");
await userEvent.click(screen.getByRole("button", { name: "Войти" }));
expect(onSubmit).toHaveBeenCalledWith({ email: "a@b.c" });
```

- Искать элементы как пользователь: `getByRole`, `getByLabelText`, `getByText`; `data-testid` — крайний случай.
- `userEvent` реалистичнее, чем `fireEvent`.
- Асинхронное ждать через `findBy…` и `waitFor`.
- Сеть мокать на уровне запросов (MSW), а не подменять модули.

@@@ react-44 | state, антипаттерн
Почему нельзя вызывать `setState` прямо в теле компонента?
???
Обновление state во время рендера запускает новый рендер, в котором снова вызывается `setState`, — бесконечный цикл (React остановит его ошибкой «Too many re-renders»).

```tsx
function Bad() {
  const [n, setN] = useState(0);
  setN(n + 1); // ✗ бесконечный цикл
  return <p>{n}</p>;
}
```

`setState` вызывают в обработчиках событий и эффектах. Исключение — подстройка state под изменившийся проп с условием, которое перестанет выполняться, но обычно лучше вычислить значение в рендере или сменить `key`.

@@@ react-45 | списки, key
Должны ли ключи быть уникальны глобально? Как задать key для Fragment?
???
Ключ должен быть уникален только **среди соседей** в одном списке — в разных списках ключи могут совпадать.

Если элемент списка — это несколько узлов без обёртки, используют полную форму `Fragment` (короткая `<>` ключ не принимает):

```tsx
import { Fragment } from "react";

{terms.map((t) => (
  <Fragment key={t.id}>
    <dt>{t.word}</dt>
    <dd>{t.meaning}</dd>
  </Fragment>
))}
```

Ключ не передаётся в компонент как проп: если id нужен внутри, передай его отдельно.
