@@@ css-01 | специфичность
Как считается специфичность селектора?
???
Тройка `(id, класс, тег)`, сравнивается слева направо:

- **id**: `#header` → `(1, 0, 0)`
- **классы, атрибуты, псевдоклассы**: `.btn`, `[type="text"]`, `:hover` → `(0, 1, 0)`
- **теги и псевдоэлементы**: `div`, `::before` → `(0, 0, 1)`

`#nav .link:hover` = `(1, 2, 0)` — победит любое число классов без id. Инлайн-стиль `style=""` сильнее селекторов, `!important` — сильнее инлайна. `*` и комбинаторы (`>`, `+`, `~`) специфичности не добавляют.

@@@ css-02 | специфичность, селекторы
Чем отличаются `:is()` и `:where()`?
???
Оба принимают список селекторов и сокращают запись:

```css
:is(header, footer) a:hover { … }
```

Разница в специфичности:

- `:is()` берёт специфичность **самого сильного** селектора из списка: `:is(#id, .cls)` весит как id;
- `:where()` всегда даёт **ноль**.

Поэтому `:where()` удобен для базовых стилей в библиотеках и ресетах — их легко перебить любым классом.

@@@ css-03 | каскад, layers
В каком порядке каскад решает, какое правило победит? Как работают `@layer`?
???
1. Происхождение и важность (стили браузера → автора; `!important` переворачивает порядок).
2. **Каскадные слои** `@layer`.
3. Специфичность.
4. Порядок в коде: при равенстве побеждает последнее правило.

```css
@layer reset, base, components;
@layer components { .btn { color: blue; } }
.btn { color: red; } /* без слоя — победит, даже при меньшей специфичности */
```

Обычные стили **без слоя сильнее любых слоёв**, а слои между собой — в порядке объявления. С `!important` всё наоборот: важное правило из слоя бьёт важное без слоя. Так устроен Tailwind v4: утилиты в `@layer utilities`.

@@@ css-04 | box model
Что такое box model и `box-sizing`?
???
Элемент состоит из content → padding → border → margin.

- `content-box` (по умолчанию): `width` — это только контент. `width: 100px; padding: 10px; border: 5px` даёт ширину **130px**.
- `border-box`: `width` включает padding и border — ровно 100px, контент сжимается.

Почти все проекты делают `*, *::before, *::after { box-sizing: border-box; }` — размеры становятся предсказуемыми.

@@@ css-05 | margin
Что такое схлопывание отступов (margin collapse)?
???
Вертикальные margin соседних блоков **не складываются**, берётся больший: `margin-bottom: 20px` + `margin-top: 30px` = **30px** между блоками.

Ещё случай: margin первого ребёнка «вытекает» наружу родителя, если у родителя нет padding, border или своего контекста форматирования.

Не схлопываются: горизонтальные отступы, элементы flex и grid, абсолютно позиционированные и float-элементы.

@@@ css-06 | позиционирование
Чем отличаются `position: relative`, `absolute`, `fixed` и `sticky`?
???
- `relative` — остаётся в потоке, сдвигается `top/left` относительно своего места; становится опорой для `absolute`-детей.
- `absolute` — вынут из потока, позиционируется относительно ближайшего предка с `position` не `static`.
- `fixed` — относительно окна (viewport), не двигается при прокрутке.
- `sticky` — ведёт себя как `relative`, пока не достигнет порога `top`, затем «прилипает» в пределах родителя.

Ловушки: `fixed` внутри предка с `transform`, `filter` или `perspective` позиционируется относительно **этого предка**, а не окна. `sticky` не работает, если у предка `overflow: hidden` или не задан порог `top`.

@@@ css-07 | z-index, stacking context
Почему `z-index: 9999` не поднимает элемент над соседним блоком?
???
`z-index` работает только внутри своего **контекста наложения** (stacking context). Если родитель создал контекст с `z-index: 1`, то всё его содержимое — даже с `z-index: 9999` — лежит ниже соседнего блока с `z-index: 2`.

Контекст создают: `position` + `z-index` (не `auto`), `opacity < 1`, `transform`, `filter`, `will-change`, `isolation: isolate`, flex- и grid-дети с `z-index`, `position: fixed/sticky`.

Решение: поднимать сам родительский контекст или вынести элемент через портал в `body`.

@@@ css-08 | flexbox
Что означает `flex: 1`? Почему flex-элемент с длинным текстом вылезает за контейнер?
???
`flex: 1` = `flex-grow: 1; flex-shrink: 1; flex-basis: 0%` — элементы делят свободное место поровну.

У flex-элементов по умолчанию `min-width: auto` — они **не сжимаются меньше своего содержимого**. Длинное слово, `white-space: nowrap` или широкий `<pre>` распирают элемент и ломают вёрстку.

Лечится `min-width: 0` (или `overflow: hidden`) на flex-элементе — тогда сработает `text-overflow: ellipsis` или переносы. В grid то же самое: `minmax(0, 1fr)` вместо `1fr`.

@@@ css-09 | grid
Чем `auto-fill` отличается от `auto-fit` в `repeat()`?
???
```css
grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
```

Оба создают столько колонок, сколько поместится. Разница, когда элементов **мало**:

- `auto-fill` оставляет пустые дорожки — элементы сохраняют ширину, справа пустое место;
- `auto-fit` схлопывает пустые дорожки до нуля — элементы **растягиваются** на всю ширину.

Это самый короткий способ сделать адаптивную сетку карточек без медиазапросов.

@@@ css-10 | flex, grid
Когда использовать flex, а когда grid?
???
- **Flex** — одномерный: раскладка в строку **или** колонку, размеры идут от содержимого. Навбары, кнопки с иконкой, выравнивание в ряд.
- **Grid** — двумерный: строки **и** колонки сразу, размеры задаёт контейнер. Макеты страниц, сетки карточек, формы с выравниванием по колонкам.

Они отлично комбинируются: grid задаёт каркас, а внутри ячеек — flex.

@@@ css-11 | выравнивание
Какие есть способы отцентрировать блок по горизонтали и вертикали?
???
```css
/* grid — короче всего */
.parent { display: grid; place-items: center; }

/* flex */
.parent { display: flex; justify-content: center; align-items: center; }

/* абсолютное позиционирование */
.child { position: absolute; inset: 0; margin: auto; width: 200px; height: 100px; }
/* или когда размеры неизвестны */
.child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }
```

Только по горизонтали блочный элемент с шириной: `margin-inline: auto`.

@@@ css-12 | единицы
Чем отличаются `px`, `em`, `rem`, `%`, `vh` и `dvh`?
???
- `px` — абсолютные пиксели CSS.
- `em` — от размера шрифта **текущего элемента** (для `font-size` — родителя); вложенные `em` накапливаются.
- `rem` — от размера шрифта корня `html`; масштабируется вместе с настройкой шрифта браузера — хорошо для доступности.
- `%` — от размера родителя (по-разному для разных свойств).
- `vh` — 1% высоты окна. На мобильных `100vh` выше видимой области из-за панелей браузера.
- `dvh` — динамическая высота, учитывает появление и скрытие панелей; `svh` и `lvh` — минимальная и максимальная.

@@@ css-13 | адаптивность
Чем container queries отличаются от media queries?
???
**Media queries** реагируют на размер **окна**. **Container queries** — на размер **родителя-контейнера**, поэтому компонент адаптируется к месту, куда его поставили: узкая колонка или широкий блок.

```css
.card-wrap { container-type: inline-size; }

@container (min-width: 400px) {
  .card { display: grid; grid-template-columns: 120px 1fr; }
}
```

Одна и та же карточка будет горизонтальной в широком блоке и вертикальной в сайдбаре — без знания о макете страницы.

@@@ css-14 | переменные, темизация
Чем CSS-переменные отличаются от переменных Sass?
???
Sass-переменные заменяются **при компиляции** и в браузере не существуют.

CSS custom properties живут **в рантайме**:

- наследуются по DOM-дереву;
- переопределяются в любом селекторе и медиазапросе;
- меняются из JS: `el.style.setProperty("--x", "10px")`.

```css
:root { --bg: #fff; }
[data-theme="dark"] { --bg: #141417; }
body { background: var(--bg, white); } /* второй аргумент — запасное значение */
```

На этом построены темы без перезагрузки и дизайн-токены.

@@@ css-15 | селекторы, has
Что такое псевдокласс `:has()`?
???
«Родительский селектор»: выбирает элемент, **если внутри** (или после него) есть подходящий элемент.

```css
/* карточка, в которой есть картинка */
.card:has(img) { padding: 0; }

/* поле формы с невалидным инпутом */
.field:has(input:invalid) label { color: red; }

/* заблокировать прокрутку, когда открыт диалог */
body:has(dialog[open]) { overflow: hidden; }
```

Раньше такое делали только через JS. Поддерживается всеми современными браузерами.

@@@ css-16 | скрытие, доступность
Чем отличаются `display: none`, `visibility: hidden` и `opacity: 0`?
???
| | Место | Клики | Скринридер |
|---|---|---|---|
| `display: none` | нет | нет | не читает |
| `visibility: hidden` | занимает | нет | не читает |
| `opacity: 0` | занимает | **да** | читает |

Ещё отличие: ребёнок с `visibility: visible` внутри `visibility: hidden` родителя **будет виден**, а у `opacity` так не выйдет. Для «скрыть визуально, но оставить скринридерам» используют класс `sr-only`.

@@@ css-17 | наследование
Какие свойства наследуются? Что делают `inherit`, `initial`, `unset`, `revert`?
???
Наследуются в основном **текстовые** свойства: `color`, `font-*`, `line-height`, `text-align`, `visibility`, `cursor`. Не наследуются блочные: `margin`, `padding`, `border`, `background`, `width`, `display`.

- `inherit` — взять значение родителя;
- `initial` — начальное значение из спецификации (для `display` это `inline`, даже у `div`);
- `unset` — `inherit` для наследуемых, `initial` для остальных;
- `revert` — вернуть стиль браузера по умолчанию (у `div` снова будет `block`).

@@@ css-18 | bfc
Что такое контекст форматирования блока (BFC) и зачем он нужен?
???
Изолированная область вёрстки: то, что внутри, не влияет на то, что снаружи.

BFC:

- **содержит float-детей** — родитель не схлопывается до нуля по высоте;
- не даёт margin детей схлопываться с margin родителя;
- не заходит под соседний float.

Создают его: `display: flow-root` (специально для этого), `overflow: hidden/auto/scroll` (но не `clip`!), `position: absolute/fixed`, `float`, `display: inline-block`. Flex- и grid-контейнеры создают свои контексты форматирования с тем же эффектом изоляции.

@@@ css-19 | изображения, адаптивность
Как сделать адаптивные изображения?
???
```html
<img
  src="photo-800.jpg"
  srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 50vw"
  width="800" height="600"
  loading="lazy"
  alt="Описание"
/>
```

- `srcset` + `sizes` — браузер сам выберет файл под ширину экрана и плотность пикселей;
- `<picture>` с `<source>` — разные форматы (AVIF, WebP) или разная обрезка (art direction);
- `width`/`height` или `aspect-ratio` резервируют место и предотвращают сдвиг вёрстки (CLS);
- `object-fit: cover` — заполнить блок без искажения пропорций.

@@@ css-20 | доступность
Что в CSS важно для доступности?
???
- **Не убирать фокус**: вместо `outline: none` использовать `:focus-visible` — обводка видна при навигации с клавиатуры, но не при клике мышью.
- **Контраст** текста к фону — не ниже 4.5:1 для обычного текста (WCAG AA).
- `prefers-reduced-motion` — отключать или ослаблять анимации для тех, у кого включено «уменьшить движение».
- Размер шрифта в `rem`, чтобы работало увеличение шрифта в браузере.
- Цвет не должен быть единственным носителем смысла: ошибку обозначают ещё иконкой или текстом.
- Крупные области нажатия на мобильных (около 44×44px).

@@@ css-21 | основы, display
Чем отличаются `block`, `inline` и `inline-block`?
???
- **`block`** (`div`, `p`, `h1`) — начинается с новой строки и по умолчанию растягивается на всю ширину родителя. Учитывает `width`, `height` и все отступы.
- **`inline`** (`span`, `a`, `strong`) — встаёт в строку текста, ширина — по содержимому. **Игнорирует** `width` и `height`, а вертикальные `margin` не раздвигают соседние строки.
- **`inline-block`** — стоит в строке, как `inline`, но размеры и отступы работают, как у `block`. Подходит для кнопок и бейджей внутри текста.

```css
a.button {
  display: inline-block; /* иначе padding сверху и снизу наползёт на соседние строки */
  padding: 8px 16px;
}
```

Ещё полезные значения: `inline-flex` (флекс-контейнер, который сам стоит в строке — частый выбор для кнопок с иконкой) и `contents` (элемент исчезает из раскладки, а его дети становятся детьми родителя; осторожно с доступностью у кнопок и списков).

@@@ css-22 | селекторы, псевдоэлементы
Чем псевдоклассы отличаются от псевдоэлементов?
???
**Псевдокласс** (`:`) — выбирает существующий элемент в определённом **состоянии** или положении: `:hover`, `:focus-visible`, `:checked`, `:disabled`, `:first-child`, `:not()`, `:has()`.

**Псевдоэлемент** (`::`) — стилизует **часть** элемента или создаёт виртуальный элемент, которого нет в DOM: `::before`, `::after`, `::placeholder`, `::selection`, `::marker`, `::backdrop`.

```css
.required::after {
  content: " *";       /* без content псевдоэлемент не появится */
  color: crimson;
}

.tooltip::before {
  content: "";
  position: absolute; /* декоративный треугольник */
}
```

Подводные камни: `::before` и `::after` не работают у элементов без содержимого вроде `<img>` и `<input>`; текст из `content` может читаться скринридером, поэтому важную информацию так не передают. Старая запись с одним двоеточием (`:after`) работает для совместимости, но правильно — `::`.

@@@ css-23 | анимации, производительность
Какие свойства дёшево анимировать, а какие дорого?
???
Дёшево — **`transform`** и **`opacity`**. Их меняет композитор (часто на GPU): раскладку и перерисовку пересчитывать не нужно, анимация идёт плавно даже при занятом главном потоке.

Дорого — всё, что меняет **геометрию**: `width`, `height`, `top`, `left`, `margin`, `padding`, `font-size`. Каждый кадр браузер заново считает раскладку страницы.

```css
/* плохо: пересчёт layout на каждом кадре */
.panel { transition: left 0.3s; }

/* хорошо: только композиция */
.panel { transition: transform 0.3s; }
.panel.open { transform: translateX(0); }
```

`will-change: transform` заранее выносит элемент на отдельный слой. Ставить его стоит точечно — на элементы, которые действительно будут анимироваться: каждый слой занимает память.

И не забывай про `@media (prefers-reduced-motion: reduce)` — для пользователей, которым движение мешает.

@@@ css-24 | рендеринг, производительность
Что такое reflow и repaint? Что такое layout thrashing?
???
После изменения стилей браузер проходит этапы:

1. **Layout (reflow)** — расчёт размеров и положения элементов. Самый дорогой этап, может затронуть всю страницу.
2. **Paint (repaint)** — отрисовка пикселей: цвета, тени, текст.
3. **Composite** — сборка слоёв в итоговую картинку.

Смена `width` запускает все три этапа, `color` — paint и composite, `transform` — только composite.

**Layout thrashing** — чередование записи и чтения геометрии в цикле. Чтение (`offsetHeight`, `getBoundingClientRect()`) после записи заставляет браузер **синхронно** пересчитать раскладку:

```js
// плохо: reflow на каждой итерации
items.forEach((el) => {
  el.style.height = `${el.offsetWidth / 2}px`;
});

// хорошо: сначала все чтения, потом все записи
const widths = items.map((el) => el.offsetWidth);
items.forEach((el, i) => (el.style.height = `${widths[i] / 2}px`));
```

@@@ css-25 | изображения, пропорции
Как сохранить пропорции блока или картинки?
???
**`aspect-ratio`** задаёт соотношение сторон, высота считается из ширины:

```css
.video { width: 100%; aspect-ratio: 16 / 9; }
.avatar { width: 48px; aspect-ratio: 1; border-radius: 50%; }
```

Раньше для этого был хак с `padding-top: 56.25%`.

**`object-fit`** решает, как картинка ведёт себя внутри блока с заданными размерами:

- `cover` — заполнить блок целиком, обрезав лишнее (обложки, аватары);
- `contain` — вписать целиком, оставив поля (логотипы, товары);
- `fill` (по умолчанию) — растянуть, искажая пропорции.

```css
.cover img {
  width: 100%;
  height: 240px;
  object-fit: cover;
  object-position: center top; /* какую часть оставить при обрезке */
}
```

Бонус: если у `<img>` указаны атрибуты `width` и `height`, браузер сам выставит `aspect-ratio` и зарезервирует место ещё до загрузки — страница не будет прыгать (CLS).

@@@ css-26 | адаптивность, функции
Что делают `clamp()`, `min()` и `max()`?
???
- `min(a, b)` — меньшее из значений: `width: min(100%, 720px)` — на широком экране 720px, на узком — вся ширина. Заменяет пару `width` + `max-width`.
- `max(a, b)` — большее: `padding: max(16px, 4vw)` — отступ не меньше 16px.
- `clamp(min, preferred, max)` — значение растёт вместе с экраном, но остаётся в границах.

```css
h1 {
  font-size: clamp(1.75rem, 1.2rem + 2.5vw, 3rem);
}

.container {
  width: min(100% - 2rem, 1100px);
  margin-inline: auto;
}
```

Это **плавная типографика** без набора медиазапросов: заголовок мягко увеличивается от телефона до десктопа.

Важная деталь: в «предпочтительном» значении смешивай `rem` и `vw`. Чистые `vw` не реагируют на масштабирование страницы пользователем — это проблема доступности.

@@@ css-27 | grid
Что такое `fr`, `minmax()` и `grid-template-areas`?
???
**`fr`** — доля свободного места: `1fr 2fr` делит остаток в пропорции 1:2.

**`minmax(min, max)`** — размер дорожки в диапазоне. Классический адаптивный ряд карточек без медиазапросов:

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(240px, 1fr));
  gap: 16px;
}
```

**`grid-template-areas`** — раскладка «картинкой»:

```css
.layout {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-areas:
    "header header"
    "sidebar main";
}
.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main    { grid-area: main; }

@media (width < 768px) {
  .layout {
    grid-template-columns: 1fr;
    grid-template-areas: "header" "main" "sidebar";
  }
}
```

Ловушка: `1fr` — это `minmax(auto, 1fr)`, и длинное слово или широкая таблица растянут колонку. Лечится `minmax(0, 1fr)`.

@@@ css-28 | адаптивность, медиазапросы
Что такое mobile-first и какие медиазапросы, кроме ширины, полезны?
???
**Mobile-first** — базовые стили пишутся для телефона, а для больших экранов добавляются через `min-width`. Мобильные устройства слабее — им достаются только базовые правила, а сложная раскладка — бонус для широких экранов.

```css
.grid { display: grid; gap: 12px; }
@media (min-width: 768px) {
  .grid { grid-template-columns: 1fr 1fr; }
}
```

Новый синтаксис диапазонов: `@media (768px <= width < 1200px)`.

Медиазапросы о **предпочтениях и устройстве**:

- `prefers-color-scheme: dark` — системная тёмная тема;
- `prefers-reduced-motion: reduce` — пользователь просит меньше анимаций;
- `hover: hover` и `pointer: fine` — есть мышь. Ховер-эффекты лучше включать только так: на тач-экране `:hover` «залипает» после касания;
- `prefers-contrast: more` — повышенный контраст.

```css
@media (hover: hover) {
  .card:hover { transform: translateY(-2px); }
}
```

@@@ css-29 | темы, переменные
Как сделать светлую и тёмную тему на CSS-переменных?
???
Цвета задаются **токенами** — переменными с ролью, а не с конкретным цветом. Тема переопределяет значения:

```css
:root {
  --bg: #ffffff;
  --text: #111111;
  --accent: #2a7bbf;
  color-scheme: light;
}

:root[data-theme="dark"] {
  --bg: #111215;
  --text: #ffffff;
  --accent: #5aa9e6;
  color-scheme: dark;
}

body { background: var(--bg); color: var(--text); }
```

- `color-scheme` перекрашивает встроенные элементы браузера: скроллбары, инпуты, календарь.
- Переключатель меняет атрибут: `document.documentElement.dataset.theme = "dark"`.
- Чтобы при загрузке не мигала светлая тема, тему из `localStorage` применяют **маленьким inline-скриптом в `<head>`**, до отрисовки страницы.

Так устроено и это приложение: файл `globals.css`, переменные `--bg`, `--surface`, `--accent`, а скрипт темы выполняется ещё до React.

@@@ css-30 | архитектура, изоляция стилей
Как изолировать стили компонентов: БЭМ, CSS Modules, CSS-in-JS, Tailwind?
???
Главная проблема CSS — глобальность: класс `.title` из одного компонента ломает другой.

- **БЭМ** — соглашение об именах: `.card__title--large`. Ничего не нужно настраивать, но всё держится на дисциплине.
- **CSS Modules** — сборщик превращает `.title` в уникальное `.Card_title__x7f2a`. Обычный CSS, изоляция автоматически.
- **CSS-in-JS** (styled-components, Emotion) — стили в JS, динамика через пропсы. Минус — стоимость в рантайме и сложности с серверными компонентами. Есть варианты с нулевым рантаймом: vanilla-extract, Panda CSS.
- **Tailwind** — утилитарные классы прямо в разметке. Не нужно придумывать имена, конфликтов нет, неиспользуемый CSS не попадает в сборку. Минус — длинные строки классов.

```tsx
import styles from "./Card.module.css";
<h2 className={styles.title} />;               // CSS Modules
<h2 className="text-xl font-semibold" />;       // Tailwind
```

На собеседовании ценят не «правильный» выбор, а понимание компромиссов: изоляция, динамика, производительность и удобство команды.

@@@ css-31 | tailwind
Как работает Tailwind CSS и что изменилось в версии 4?
???
Tailwind сканирует исходники проекта, находит используемые классы (`flex`, `p-4`, `text-mute`) и генерирует CSS **только для них**. Поэтому итоговый файл маленький, хотя возможных классов тысячи.

Важное следствие — имя класса должно встречаться в коде **целиком**:

```tsx
<div className={`text-${color}-500`} />       // не сработает: такой строки в коде нет
<div className={color === "red" ? "text-red-500" : "text-blue-500"} /> // сработает
```

Что нового в v4:

- настройка **в CSS**, а не в `tailwind.config.js`: `@import "tailwindcss"` и `@theme { --color-brand: #5aa9e6; }` — токены сразу становятся и классами (`bg-brand`), и CSS-переменными;
- исходники находятся автоматически, `content` указывать не нужно;
- новый движок — сборка в разы быстрее;
- современный CSS внутри: каскадные слои, `color-mix()`, container queries без плагина (`@container`, `@md:`).

Это приложение использует Tailwind 4 — посмотри блок `@theme` в `globals.css`.

@@@ css-32 | текст, overflow
Как обрезать длинный текст многоточием в одну или несколько строк?
???
**Одна строка:**

```css
.title {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

Нужны все три свойства. Во flex-контейнере элементу ещё нужен `min-width: 0` — иначе он не сожмётся меньше длины текста.

**Несколько строк** (поддерживается всеми браузерами, хоть и с префиксом):

```css
.excerpt {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 3;
  overflow: hidden;
}
```

В Tailwind — `truncate` и `line-clamp-3`.

Для длинных слов без пробелов (ссылки, хеши) — `overflow-wrap: anywhere`, чтобы они переносились, а не ломали вёрстку.

Не забывай про доступность: обрезанный текст должен быть доступен целиком — во всплывающей подсказке, по клику или на отдельной странице.

@@@ css-33 | фокус, доступность
Чем отличаются `:focus`, `:focus-visible` и `:focus-within`?
???
- **`:focus`** — элемент в фокусе, неважно как: клик мышью, тап или Tab.
- **`:focus-visible`** — фокус, который **стоит показать**. Браузер решает сам: при навигации с клавиатуры — да, при клике мышью по кнопке — нет. Для текстовых полей — всегда.
- **`:focus-within`** — у элемента в фокусе он сам или **любой потомок**. Например, подсветить всю форму поиска, когда фокус в инпуте.

```css
button:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
}

.search:focus-within {
  box-shadow: 0 0 0 2px var(--accent);
}
```

Классическая ошибка — `*:focus { outline: none }` ради «красоты». Пользователи клавиатуры перестают видеть, где находятся. Правильно — убирать обводку только там, где её не просят, через `:focus-visible`.

@@@ css-34 | селекторы, основы
Какие есть комбинаторы и селекторы атрибутов?
???
**Комбинаторы:**

- `A B` — потомок на любом уровне вложенности;
- `A > B` — только прямой ребёнок;
- `A + B` — соседний элемент сразу **после** A;
- `A ~ B` — все соседи после A.

```css
.menu > li { }                 /* только пункты верхнего уровня */
h2 + p { margin-top: 0; }      /* первый абзац после заголовка */
input:checked ~ .panel { display: block; }  /* показать панель после отмеченного чекбокса */
```

**Селекторы атрибутов:**

```css
[disabled] { }                    /* атрибут есть */
[type="email"] { }                /* точное значение */
a[href^="https://"] { }           /* начинается с */
a[href$=".pdf"]::after { content: " (PDF)"; }  /* заканчивается на */
[class*="icon-"] { }              /* содержит */
[data-state="open"] { }           /* data-атрибуты — удобный способ стилизовать состояние */
```

Селекторы атрибутов по специфичности равны классу. Состояние через `data-*` и `aria-*` (например, `[aria-expanded="true"]`) заодно помогает доступности.

@@@ css-35 | селекторы, nth-child
Как работают формулы в `:nth-child()`?
???
Формула `An+B`: `n` пробегает 0, 1, 2… и подходят элементы с полученными номерами (нумерация с 1).

```css
li:nth-child(2n) { }        /* чётные: 2, 4, 6 — то же, что even */
li:nth-child(2n+1) { }      /* нечётные — odd */
li:nth-child(3) { }         /* только третий */
li:nth-child(n+4) { }       /* с четвёртого и дальше */
li:nth-child(-n+3) { }      /* первые три */
li:nth-last-child(-n+2) { } /* последние два */
```

Ловушка: `:nth-child` считает **всех** детей, а не только подходящих под селектор. `p:nth-child(2)` выберет второй элемент, только если это `p`.

Решения:

- `:nth-of-type(2)` — второй по счёту **среди элементов того же тега**;
- `:nth-child(2 of .visible)` — второй среди элементов с классом `.visible`. Удобно для «зебры» в таблице с отфильтрованными строками.

Ещё полезное: `:only-child` — единственный ребёнок, а `li:first-child:nth-last-child(4)` вместе с `li:first-child:nth-last-child(4) ~ li` выбирают все пункты, только если в списке ровно 4 элемента.

@@@ css-36 | логические свойства, i18n
Что такое логические свойства (`margin-inline`, `inset`)?
???
Вместо физических направлений (left, right, top, bottom) — направления относительно **потока текста**:

- `inline` — вдоль строки (в русском — слева направо);
- `block` — поперёк строк (сверху вниз);
- `start` / `end` — начало и конец.

```css
.card {
  padding-inline: 16px;          /* padding-left + padding-right */
  margin-block: 24px 0;          /* margin-top и margin-bottom */
  border-inline-start: 3px solid var(--accent); /* слева, а в арабском — справа */
  inline-size: min(100%, 600px); /* аналог width */
}

.overlay {
  position: fixed;
  inset: 0;                      /* top, right, bottom, left = 0 */
}
```

Зачем: для языков с письмом справа налево (арабский, иврит) раскладка отзеркалится сама, без отдельных стилей. А ещё это просто короче: `margin-inline: auto` центрирует блок.

Tailwind использует логические свойства в классах `ms-4`, `pe-2`, `px-4` и `inset-0`.

@@@ css-37 | синтаксис, вложенность
Что такое нативная вложенность CSS (CSS Nesting)?
???
Возможность писать вложенные правила, как в Sass, — прямо в CSS, без сборки. Поддерживается всеми современными браузерами.

```css
.card {
  padding: 16px;

  & .title { font-weight: 600; }       /* .card .title */
  &:hover { background: var(--surface-2); }  /* .card:hover */
  &.active { border-color: var(--accent); }  /* .card.active */

  .theme-dark & { background: #111; }  /* .theme-dark .card */

  @media (width >= 768px) {
    padding: 24px;
  }
}
```

`&` — ссылка на родительский селектор. Для потомков его можно не писать: `.title { }` внутри `.card` тоже станет `.card .title`.

Отличие от Sass: нельзя склеивать части имени, как `&__title` в БЭМ, — `&` подставляется как целый селектор. Специфичность вложенного правила считается так, будто родитель обёрнут в `:is()`.

Совет: не уходить глубже 2–3 уровней — иначе селекторы становятся длинными и слишком специфичными.

@@@ css-38 | прокрутка, карусель
Как сделать карусель с «примагничиванием» на чистом CSS?
???
Через **scroll snap** — браузер сам доводит прокрутку до ближайшего элемента:

```css
.carousel {
  display: flex;
  gap: 16px;
  overflow-x: auto;
  scroll-snap-type: x mandatory;   /* ось и строгость */
  scroll-padding-inline: 16px;     /* отступ точки привязки от края */
  overscroll-behavior-x: contain;  /* не прокручивать страницу и не листать историю */
}

.carousel > * {
  flex: 0 0 85%;
  scroll-snap-align: start;        /* к какому краю примагничивать */
}
```

- `mandatory` — всегда останавливаться на элементе; `proximity` — только если рядом;
- `scroll-snap-stop: always` — не пролистывать несколько слайдов одним свайпом.

Плюсы перед JS-слайдером: родная инерция прокрутки на телефоне, работает с клавиатурой и колесом, нулевой JS. Стрелки «вперёд/назад» добавляются парой строк: `carousel.scrollBy({ left: carousel.clientWidth, behavior: "smooth" })`.

@@@ css-39 | анимации, view transitions
Что такое View Transitions API?
???
API для плавной анимации между двумя состояниями страницы. Браузер делает «снимок» до изменения, применяет изменения DOM и анимирует переход между снимками:

```js
document.startViewTransition(() => {
  renderNewState(); // любое обновление DOM
});
```

По умолчанию — плавное перетекание. Элементы с одинаковым `view-transition-name` в старом и новом состоянии анимируются как **один объект**: карточка в списке «перелетает» в заголовок страницы деталей.

```css
.card-image { view-transition-name: hero; }

::view-transition-old(root),
::view-transition-new(root) {
  animation-duration: 0.3s;
}
```

Для многостраничных сайтов есть переходы между документами: `@view-transition { navigation: auto; }`. В React есть компонент `<ViewTransition>`, который запускает такие анимации при обновлениях внутри transition, — им анимируются переходы между экранами этого приложения (`app/elements/Page.tsx`).

Где нет поддержки, изменения просто применяются без анимации — это безопасное прогрессивное улучшение.

@@@ css-40 | grid, subgrid
Что такое `subgrid` и какую проблему он решает?
???
Классическая боль: в ряду карточек у одной заголовок в две строки, и кнопки «Купить» оказываются на разной высоте. Каждая карточка — отдельная сетка, и они ничего не знают друг о друге.

`subgrid` позволяет дочерней сетке **использовать дорожки родителя**:

```css
.cards {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
}

.card {
  display: grid;
  grid-row: span 3;                /* карточка занимает 3 строки родителя */
  grid-template-rows: subgrid;     /* и использует их как свои */
}
/* внутри карточки: картинка, заголовок, кнопка — по строке на каждый */
```

Теперь строки «заголовок» у всех карточек ряда одинаковой высоты (по самому длинному), и кнопки выровнены.

Работает и для колонок: например, выровнять подписи и поля формы, вложенные в разные блоки. Поддерживается всеми современными браузерами с 2023 года.
